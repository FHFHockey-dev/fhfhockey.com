# Repository player-projection inventory

This is the human-readable index to the exhaustive machine register in [`model-inventory.json`](./model-inventory.json). The JSON record is authoritative for language, owner, population, target, horizon, vintage, strength state, output type/distribution, inputs/providers/coverage, writers, tables/files, jobs, API/UI consumers, training/inference/evaluation, tests, artifact handling, versioning, as-of behavior, leakage risk, disposition and unresolved questions.

The inventory describes repository state, not statistical validity. No live Supabase data was queried. `supabase/migrations/` is the active schema authority; root `migrations/`, `web/sql/`, `web/supabase/migrations/` and `supabase/migration-archive/` are historical or design evidence unless an active migration incorporates them.

## Classification key

- **Trained model**: fitted parameters or model artifacts exist.
- **Weighted formula / heuristic probability**: hand-authored coefficients, bounds or rules produce forecast-like values.
- **Simulation**: samples or mixtures values from assumed distributions/scenarios.
- **Feature / rolling pipeline**: creates inputs or descriptive histories rather than a future outcome.
- **Sustainability / ranking / display**: descriptive or product transforms that must not be treated as forecasts.
- **Evaluation / serving**: scores, persists or exposes another system's output.
- **Unused experiment**: no supported runtime caller or valid production evidence.

## Inventory conclusion

No current player system qualifies as the final empirically validated architecture. FORGE is a functioning production heuristic with reusable surrounding contracts, sustainability is descriptive, sKO is quarantined or stale, and external annual projections are product inputs/benchmarks. The xG and team-game systems are adjacent governance exemplars, not proof of a transferable player model.
