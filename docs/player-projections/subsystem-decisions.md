# Reuse, refactor and greenfield subsystem decisions

These are repository-integration decisions, not a choice of statistical model. “Replace core” preserves compatible surrounding contracts while reserving the model family, target construction, windows, coefficients, thresholds and calibration method for the final Deep Research Report.

Relative effort is scoped to repository migration after the research architecture is approved: **S** (bounded), **M** (several connected components), **L** (cross-cutting), **XL** (new governed subsystem plus migration/backfill).

## Decision distribution

| Decision | Subsystems | Meaning for implementation |
| --- | --- | --- |
| Keep | none as a complete subsystem | Even the strongest foundations need contract extension or extraction for the new player system. |
| Refactor | 1, 2, 3, 4, 20, 21, 24, 25 | Preserve ownership and substantial implementation while adding missing historical/version/distribution semantics. |
| Extract | 5, 18, 22, 23 | Reuse selected utilities and patterns, not the enclosing analytics/model. |
| Replace core | 7, 8, 10, 11, 13, 14, 15, 16, 17, 19 | Preserve surrounding data/serving where compatible; replace empirically unsupported forecasting logic. |
| Greenfield subsystem | 6, 9, 12 | No current subsystem meets the required semantics; use existing patterns without inheriting incompatible state. |
| Retire after migration | tracked in `duplicate-retirement-ledger.md` | Retirement applies to concrete legacy components, not one of the 25 target capabilities as a whole. |
| Defer | no repository-integration layer | Statistical choices inside replace/greenfield decisions remain deferred to research, but the repository disposition is actionable now. |

## Overall disposition

The likely implementation is **hybrid**: primarily refactor/extract for data, identity, orchestration, persistence, evaluation patterns and serving; primarily replace/greenfield for player statistical models, immutable feature snapshots and skater availability. This conclusion is driven by semantic alignment and historical reproducibility, not by a preference for old or new code.
