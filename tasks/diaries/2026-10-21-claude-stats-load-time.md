- Scope: diagnose slow /stats routes (done, reported); then fix the team dashboard load path (TJ approved): parallel queries, stop restart, progressive render, Shot Map data only on its tab, bounded league queries; measured locally before/after.
- Where: octoberBranch, uncommitted, on top of uncommitted S01 work.
  - Changed: web/components/TeamDashboard/TeamDashboard.tsx (+test), web/hooks/useShotData.ts (enabled flag + loaded-key cache), web/pages/stats/team/[teamAbbreviation].tsx (enables shot data only for ?tab=visualization), __tests__/pages/stats/team/teamAbbreviation.test.tsx (router mock + Shot Map gating test).
- What changed in TeamDashboard:
  - The 4 primary reads run in one Promise.all, and the dashboard renders as soon as they land.
  - Goaltending (3 NHL proxy calls, now parallel) and league rankings (4 reads, parallel) load afterwards with "Loading…" / "#…" placeholders.
  - League advanced and special-teams ranks now come from per-team season totals (date-bounded, gp>0, count columns only, paginated) instead of each team's latest single game row.
- Restart: NOT changed. Several existing tests deliberately require an explicit season to start without waiting for the current-season lookup. Measured cost is about 80 ms plus one wasted round of primary reads.
