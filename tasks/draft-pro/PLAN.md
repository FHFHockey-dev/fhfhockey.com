## Product invariants
- US$5.99 one-time Stripe-hosted Checkout with Link; season `draft_pro_2026_27`, expiration `2027-07-01T04:00:00Z`. No renewal. Bank payouts; no PayPal integration.
- Verified active paid Patreon membership in configured FHFH campaign independently grants Pro. Follow paid eligibility through cancellation until paid access expires. Never allow free tiers to qualify. Purchased pass survives Patreon loss.
- Retain entitlement history and premium data on revocation/disconnect. Lock premium payload read/export/write/calculation, allow owned item names/status. Remove disconnected credentials. Restore retained work upon renewed eligibility. Preserve free local draft.
- Free: full manual draft, keepers/trades, scoring/roster settings, source selection/weights, local CSV imports, local autosave/bookmarks, standard suggestions, favorites, basic two-player compare, undo/correction/basic summary.
- Pro: roster-aware recommendations, recommendation-only personalized replacement, DUST insights/alternatives/schedule-fit sort, blended CSV, Saved Drafts/private imports, scenarios, reports; Yahoo only after independent readiness validation.
- Refund requests: case-by-case, submitted within 168 hours from first server-recorded purchase activation, one open request/purchase. Required reason and 10–2000 character explanation; optional improvement/live-draft-use questions. Persist before Resend email to tim@fhfhockey.com. No automatic refunds or access revocation on request. Manual Stripe refunds reconcile through webhook. Patreon refunds stay at Patreon.
- Saved Drafts: 10/account; 10 MiB normalized private imports/draft, 100 MiB/account. Latest state only, optimistic lock version, two-second debounce cloud autosave; local autosave always free. Persist settings/picks/keepers/trades/team/source weights/import mappings+rows/favorites/notes/tiers/recommendation preferences. Upload only on explicit Save to account. Private imports separate from lightweight snapshot. Conflict: reload or save as another; never overwrite silently. Confirm replacement of differing local work.

## Architecture
- Reuse existing user_entitlements, authenticated API conventions, Pages Router, Supabase and SCSS. One server access resolver, no user_metadata authorization. Ownership+eligibility at API and direct database/storage boundary. RLS/grants, server-only provider writes, no public private-file URLs.
- Access response: eligibility, granting sources, expiration/verification time, reason, capabilities, provider readiness separately.
- Shared pure calculation functions; hooks are adapters. No separate server/client formulas. Premium APIs validate bounded inputs/rate limits; debounce/abort stale client requests. Free render must not request paid calculations.
- Routes: GET /api/v1/account/draft-pro; POST .../checkout, .../checkout/verify, .../refund-requests; /api/v1/webhooks/{stripe,patreon}; /api/v1/account/draft-pro/drafts and /{id}; /api/v1/draft-pro/{recommendations,dust,export}; /api/v1/account/draft-pro/{scenarios,reports}. 401 unauthenticated, 403 inactive/capability reason, 409 conflicts.
- Stripe server-owned price/product/currency/user/date, one quantity/payment mode, persist attempt, prevent duplicate checkout/rebuy, shared idempotent fulfill for webhook+return. Signature/raw body; duplicate/concurrent/out-of-order events. Full refund revokes purchase, partial retains; open dispute suspends, won restores only eligible season; other grants unaffected.
- Patreon API v2 webhooks + hourly reconciliation. Maximum verification age one hour; stale check on premium access. Failed verification preserves records, returns verification-unavailable, blocks stale premium operations. No cancellation-renewal shortcut to expiry. Keep account ownership across reconnect.
- Feature flags: checkout, premium enforcement, Saved Drafts, scenarios/reports, Yahoo readiness. All initial work local/test; no production writes, pushes that trigger deployment, remote builds, live money/account changes, or provider activation without owner authorization. Secrets must not be printed/copied into docs.

## Chef acceptance and operating rules
- Tasks work only in isolated worktrees; no pushes, deployments, shared checkout writes, autonomous scope expansion or extra task spawning. Local scoped commits required at handoff. Report commit/files/behavior/exact checks/risks/integration requirements.
- Chef owns integration branch codex/draft-pro and this ledger. At most three implementation tasks active. Dependencies wait without exploring or coding; send a short queued acknowledgement and end until released. Rebase onto provided checkpoint before beginning.
- Chef reviews diff/contracts/tests, sends precise critiques, approves then integrates, releases dependents. Done is not approval. Check suspected lack of progress around ten minutes once; get precise blocker/attempts/next step rather than polling.
- Starting models as above. Escalation needs recorded reason/scope/exit; Terra/high for concrete complexity, Sol only after focused attempts fail. Downgrade once resolved. No speculative duplicate implementations.
- Nearest tests first, type/lint at integration, full unit suite once per release candidate. Browser tests plus isolated two-user DB/RLS/storage and real Stripe test-mode checkout/webhooks are required evidence; report unavailable external prerequisites honestly. No routine production build.
- Release packet: commits/migrations/evidence/config names/rollout/rollback. Preserve work and entitlements when disabling features. Required owner external authorizations remain final gates.
