## Evaluation and verification

Ran from `web/`: `npm test -- lib/sources/tweetInterpretation.test.ts lib/sources/playerIdentity.test.ts lib/sources/projectedLineups.test.ts`: **3 files, 35 tests passed**. The local diagnostic replay ran for 11 stored contexts. No full-route replay, AI inference, application build, deployment, migration, production correction or backfill ran. Schema-query error for nonexistent queue `tweet_posted_at` was resolved by using its actual `tweet_created_at` field.

Initial annotation pool: 11 regressions + 24 real distinct-ID holdout candidates from a bounded 80-row September 28–30 snapshot read. Candidate classes span lineup, practice, goalie, injury, other and PP. This is a collection pool, not a frozen labeled evaluation set or representative sample. Deduplicate and group relay/original/thread/near-duplicate families before split; some candidates may overlap semantically with seeds. Select at least two independent reviewed source examples for each required class/control where available; fetch only uncovered classes after this pool is reviewed. Document final counts and unavailable categories rather than manufacturing a sample-size guarantee.

Use seeds for development regressions, separate held-out source families for evaluation, and retain correct existing cases. Freeze expected claim annotations, rosters/aliases at publication, source text, dates/timezones, configuration/version manifest and split before tuning. Labels must reflect inference possible at publication, never eventual outcome or later roster changes. A second reviewer must resolve disputed identities/certainty; keep disagreement/review labels rather than force positives.

Required controls: non-injury out/off/return; quoted speculation; historical/current comparison; multi-team/multi-player posts; ambiguous surnames/initials; genuine hyphenated names; slash alternatives; partial PP/ES and tentative swaps; practice/warmup/first-off observations; negative availability, continuing injury, corrections and unsupported pronouns. Extend nearest tests, including existing processor API mocks, sourceObservations tests and projectedLineups tests. Assert exact source spans, independent claim outcomes, non-mutation of confirmed fields, preserved ordinals, full/partial eligibility, continuity, same-input idempotency, duplicates, version changes, retractions and out-of-order arrival. Trace public consumption with safe mocks/test storage.

Report false confirmed claims and wrong canonical IDs with denominators; per-class precision/recall only on reviewed labels, plus claim/post review and abstention rates. Keep regression and holdout results separate. Compare equivalent route paths with frozen enrichment and storage mocks; standalone parser versus historical whole pipeline is not improvement evidence.
