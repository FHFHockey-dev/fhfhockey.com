## New executable rules

1. Names are **SKO Outlook**, **VuDu**, **Sustainability Gap**, and **Expected Production** (`P2-TICKET.md:47-54`). Expected Production is a model estimate, not latent truth or market value. This local Phase0 module does not change any runtime reader or UI.
2. `D=M-R`; return native `gap` plus `orientedGap=-D` when lower-is-better, otherwise D. Positive oriented gap means favorable rebound; negative means cooling. Each operand carries `{value,basis}`; both must equal the requested basis even when a value is missing. Bases are `per_scheduled_team_game`, `per_appearance`, `per_60`, `per_100_on_net_shots` (`web/lib/sko/gap.ts:1-44`; `PLAN-EXCERPTS.md:8-14`). Target, strength, source vintage, original cutoff, forecast horizon, recent-window eligibility and context matching remain caller preconditions; this numeric module cannot certify them.
3. Preserve `null`/`undefined` input as `{gap:null,orientedGap:null,basis}`; absence never becomes zero. Nonfinite numeric input/output is invalid and throws. Observed zero with positive exposure remains a valid zero (`gap.ts:14-18,36-44,56-69`; tests `gap.test.ts:70-79,92-101,114-139`).
4. `displayScore=100*tanh(orientedGap/scale)` requires finite gap and finite positive scale. Scale is fixed per target/horizon/basis and has **no production default**. The illustrative 0.4 exists only in tests. Score is a display normalization, not probability/confidence/quality; zero means no modeled gap, not stable (`gap.ts:47-53`; `PLAN-EXCERPTS.md:15-23`).
5. `watchLabel` takes an explicit finite nonnegative **native-unit** threshold; positive/negative gaps meeting its inclusive magnitude boundary yield **Rebound watch / Cooling watch**. Zero, missing, or subthreshold gap yields null; threshold zero still gives no label for exact zero. No empirical threshold is selected (`gap.ts:99-111`; tests `gap.test.ts:103-112`). No Buy low/Sell high label, streak probability, duration forecast or ten-game stabilization rule is created (`P2-TICKET.md:53-54`; `PLAN-EXCERPTS.md:43-45`).
6. `vuduSaveGap=100*(expectedSaveProb-totalSaves/totalShotsOnNet)`, probability in [0,1], nonnegative finite counts. Missing inputs or zero shots return null; zero exposure returns null even if saves is positive. Positive-exposure saves cannot exceed shots. Keep native on-net shot universe; no unblocked-attempt xG divided by official shots (`gap.ts:72-97`; tests `gap.test.ts:81-101,126-139`). No shot-quality or starts model is introduced.
7. `rateFromTotals` divides summed numerator by summed exposure; missing or zero denominator returns null, negative/nonfinite denominator throws. A valid negative numerator is allowed for scored categories. SV%=sum saves/sum on-net shots; GAA=60*sum GA/sum minutes (or 3600*GA/seconds). Never average individual ratios (`gap.ts:55-69`; tests `gap.test.ts:81-101`; `PLAN-EXCERPTS.md:28-31`).
8. Confidence, coverage, uncertainty, role/opportunity, availability and absolute quality stay separate from this gap and display normalization. League points aggregation must use actual scoring weights before comparing same-basis totals; category leagues start with vectors, not arbitrary averaged sustainability scores (`PLAN-EXCERPTS.md:24-35`).
