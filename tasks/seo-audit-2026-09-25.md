# FHFH SEO audit and local fixes

Scope: bounded audit of the Pages Router app, metadata, crawl discovery, recovery navigation, and a draft sitewide privacy structure. Local changes only; no deployment, remote build, submission, or production data change.

## Priorities and evidence

| Priority | Finding | Local resolution |
| --- | --- | --- |
| P1 | The live sitemap contained 92 URLs, including `/auth`, callbacks, `/db`, and account utilities. `web/next-sitemap.config.js` excluded only `/404`. | Shared route policy in `web/lib/seo.js`; sitemap exclusions and rendered noindex for account/auth/admin, explicit sandbox routes, and unfinished privacy content. Crawling remains allowed so robots can see noindex. |
| P1 | Live `/stats/player/not-a-player` returned HTTP 200; the route returned `player: null` for malformed IDs and missing records. | Invalid or missing players now return `notFound: true`; database failures remain errors instead of being misclassified as missing players. Invalid Game Grid modes also return 404. |
| P1 | The live sitemap contained no player-detail URLs. `/stats` supplied 27 server-rendered player links, while player search is interactive. | Added `/server-sitemap.xml`, using paginated public player IDs and currently published Sanity slugs. Advertised through the existing next-sitemap robots generator. Both supported forecast mode URLs are now explicitly included. |
| P2 | Public player and blog landing responses lacked canonicals. Several main pages had generic or missing descriptions. | Shared absolute canonicals strip query/fragment variants; clearer metadata for Home, Blog, Stats, Game Grid, and Draft Dashboard. Existing page-specific canonicals still override the defaults. |
| P2 | Default social image and Sanity article canonical URLs depended on a site URL environment variable with no fallback. Production values were valid; unset environments could produce `undefined/...` URLs. | One site URL fallback and trailing-slash normalization, corrected Open Graph locale, descriptive image alt text, and default image inheritance when an article has no image. |
| P2 | The 404 was a banner without recovery actions. No sitewide privacy route existed; a scoped Draft Pro notice did exist. | Branded 404 with home/tool/article links and reused player-search dialog; `/privacy` draft with factual sections and footer link. Both preserve noindex; missing URLs retain HTTP 404. |

Live evidence was obtained from public GETs of [robots.txt](https://fhfhockey.com/robots.txt), [sitemap.xml](https://fhfhockey.com/sitemap.xml), Blog, Stats, and representative player/article URLs. The worker's curl retrieval required `-k` because its local certificate verification failed; the web retrieval tool could not open the robots/sitemap URLs. Treat this as an HTTP/content snapshot, not TLS validation or a Search Console indexing report.

The build sitemap already included a prerendered Sanity article. The gap was newly published post-build content and server-rendered player routes, not all dynamic routes. Existing Substack mirrors intentionally canonicalize to the original Substack article and remain excluded from the sitemap. Build-time lastmod timestamps are disabled because rebuilding alone does not establish content modification.

The route policy implements [Google's noindex guidance](https://developers.google.com/search/docs/crawling-indexing/block-indexing): a crawler must be allowed to retrieve a page to see its noindex directive. Canonicals follow [Google's canonical URL guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls). Search directives do not change authentication or authorization.

## Existing content and navigation

- Public navigation uses real links. Game Grid, Blog, and Underlying Stats remain standalone desktop links; the existing navigation implementation was preserved.
- `/blog` supplies server-rendered article links and article pages render published content. Metadata now describes the useful content already present rather than adding keyword filler.
- Player statistics already have individual titles and descriptions. The new shared canonical and sitemap improve discovery without changing player analysis.
- Lower-priority, route-specific metadata and editorial expansions outside the inspected primary pages remain future work. This was not an exhaustive crawl or a performance audit.

## Verification

- Passed: all 9 relevant Chromium tests across existing navigation (5) and new SEO/recovery/privacy tests (4), using targeted reruns after corrections. Desktop and mobile screenshots were inspected.
- The SEO browser tests suppress only development HMR websocket messages: on-demand compilation on the shared dev server was reloading 404 pages during interaction checks. A separate test assumption was corrected because Chrome first clears populated search inputs on Escape; closing the dialog with its button correctly restores focus.
- Passed: local runtime sitemap HTTP 200, XML content type, five-minute shared cache, 4,417 player URLs plus five Sanity articles, no duplicates/private paths. These counts reflect local configured sources, including the local Sanity dataset, not production totals.
- Passed: rendered Blog metadata, a Sanity article canonical, and preservation of an external Substack canonical/social preview; true 404 for missing pages, malformed players, and invalid forecast modes; auth and privacy noindex.
- Passed: targeted ESLint, with one pre-existing `<img>` warning in the player detail page and no errors; diff whitespace check.
- Passed: final TypeScript check (`NODE_OPTIONS=--max-old-space-size=6144 npx tsc --noEmit`). An earlier check identified unsupported top-level await in the new test; that was moved inside async test cases before the successful check.
