# Independent RSO offline settlement/readback review — 2026-11-01

Two findings remain: one P2 readback chronology defect and one P3 settlement timestamp-validation defect. The complete-strength calculation, unknown/zero handling, identity preservation, DST floor and explicit version passthrough otherwise behave as documented. No source fix was made.

**P2 — An offset-free readback capture time can pass or fail integrity depending on the machine timezone.** [normalize-readbacks.ts:12](/Users/tim/Code/fhfhockey.com/tasks/artifacts/rso-resume-2026-11-01/release-prep/qualification-capture/normalize-readbacks.ts:12) accepts any finite `Date.parse(capture.observedAt)`, then copies the original string to both consumers' normalized output. It does not require `Z` or a numeric timezone offset. With identical saved input `observedAt: "2026-11-02T18:00:00"`, issued time `22:05Z` and scheduled start `00:00Z` the next day, the actual integrity checker reports `readback_before_issue` under `TZ=UTC` but passes under `TZ=America/New_York` (where that same string becomes `23:00Z`). This makes prospective timing evidence dependent on the execution environment. Require an explicit timezone-bearing valid timestamp at the E2 boundary; preserve the original value or normalize its instant consistently. Add a regression proving offset-free clocks are rejected under both timezones. The shared `scope()` affects both RSO and Start Chart; the reproduced consumer is Start Chart.

**P3 — E3 accepts impossible calendar timestamps and emits them as observed settlement evidence.** The [clock parser at normalize-settlement.mjs:5](/Users/tim/Code/fhfhockey.com/tasks/artifacts/rso-resume-2026-11-01/release-prep/qualification-capture/normalize-settlement.mjs:5) checks an offset-shaped suffix but relies on permissive `Date.parse` for validity. With a valid November 30 slate, `capture.observedAt: "2026-11-31T17:00:00Z"` and source `updated_at: "2026-11-31T03:00:00Z"` are accepted and interpreted as December 1. The adapter emits `actual: 3`, `settlementStatus: "observed"` and the unchanged impossible timestamps; the actual integrity checker passes with one settled row. The standalone capture date has a calendar round-trip check, but the timestamps do not. Reject impossible dates before chronology calculations for capture, source, issue and scheduled clocks; include end-of-month/leap-day cases. This is a validation defect, not an error in the New York noon conversion.
