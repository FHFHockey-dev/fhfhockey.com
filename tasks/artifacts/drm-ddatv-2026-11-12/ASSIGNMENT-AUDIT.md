## Exact current algorithm and consumers

`web/components/DateRangeMatrix/lineCombinationHelper.ts`:

1. Clone every player and recalculate `comboPoints = 4*nLine1 + 3*nLine2 + 2*nLine3 + nLine4 + 3*nPair1 + 2*nPair2 + nPair3`. A supplied `comboPoints` is overwritten. Counts are per-game inferred-rank appearances, not observed minutes or recency weights.
2. Sort descending score, then ascending numeric player ID. Split F/D using `playerType` if truthy; otherwise derive from `displayPosition || position`, uppercased. The actual imported `utilities.ts:isForward/isDefense` recognize only exact `LW/RW/C` and `D`. Therefore an explicit F admits `C/RW`, while absent-type `C/RW` is unknown. This fallback distinction is not proof the validated aggregate path currently emits untyped multiposition players.
3. Pick the first unassigned player as pivot. Add the pivot to a single global ID set. Sort all remaining players of that role by this pivot's `mutualSharedToi`; if that entire property is absent, use this pivot's `percentToiWith`. An empty seconds map is present, so it suppresses percentage fallback. Missing partners default to zero. Ties use descending combo score, then ascending ID.
4. Take two forward partners or one defense partner and mark them assigned immediately. No positive-overlap, common-game, three-way intersection, LW/C/RW completeness, or minimum-duration condition applies. Neither the relationship between two chosen forward partners nor an alternative global grouping is evaluated.
5. Remove all assigned IDs from that role's candidate list and repeat. An incomplete last group is discarded and terminates that role's loop. `line-combination` truncates completed groups to four lines/three pairs. `full-roster` retains every complete group, but still does not return incomplete groups in its line/pair arrays.

`fetchAggregatedData.ts:buildAggregatedPlayers` sums accepted mirrored unordered pair/game facts once in each direction, counts per-game labels, and computes own-TOI percentages from the same included seconds. `useDateRangeMatrixData.ts:mapAggregatedPlayers` preserves those fields and checks canonical team/identity. Its final `useMemo` calls this helper once for both matrix and cards; total-TOI mode still requests capped card groups. There is no strength parameter to the helper.

`index.tsx:DateRangeMatrixInternal` flattens only completed/capped groups in line-combination mode; full-roster ordering appends remaining players by ATOI. Thus leftover players are absent from line-combination but remain available in full-roster matrix. `LinePairGrid.tsx` independently caps cards at four lines/three pairs even when the shared helper produced more. Its `orderForwardLineForPresentation` assigns exact LW/C/RW slots, then multiposition matches, then remaining players by ATOI. It changes presentation order only; three centers can still form a line. Goalies/unknown roles never enter inferred lines/pairs; cards separately select up to two goalies.

Persisted daily `shift-charts.ts:generateTeamLogs` has an earlier greedy all-strength inference: highest unassigned game-TOI forward/defender is pivot; choose its largest pair overlaps; remove players. It can emit incomplete groups and has no explicit ID tie-break in those comparators. Those inferred daily labels feed the aggregate frequency score; they are not independent evidence of observed lines. Prior report's actual daily-function probes are reused, not rerun.

## Measured units versus pairwise inference

A measured forward trio duration is the total length of simultaneous intersection of all three forwards' canonical intervals within the same game/team and qualified strength timeline. A measured defense pair needs both defenders' intersection in the chosen strength state. A measured PP unit uses the simultaneous full relevant skater set, including mixed F/D composition; the current 3F/2D-separated helper cannot represent it. Pair seconds alone cannot establish trio or five-player coincidence. Even a rule requiring all three pairs to overlap positively cannot recover an exact three-way duration.

Strength is a separate necessary input. Current all-strength pair maps and legacy `es_shifts` (non-PP, includes PK) cannot be relabelled as exclusive ES. An exact unit enumerator can be physically correct yet misclassify seconds if fed the known-unqualified strength clock. The existing helper also enforces one appearance per player across all groups; a real player may occur in multiple observed units over a date window.
