# Historical source backend receipt

- New files only: `web/lib/sources/lineHistory.ts`, its test, `web/pages/api/v1/lines/history.ts`, and its route test. Existing source/DRM/shift files untouched. No schema changes or writes.
- GET query: required `teamId`, real inclusive ISO `startDate`/`endDate`; `mode=game` defaults to game-date browse, `mode=publication` browses indexed legacy reports, `mode=claimPublication` independently browses retained canonical claims by original publication date; optional opaque per-mode `cursor`. Root owns the UI. Publishing flags gate all streams without any query when disabled.
- DTO exports `LineHistoryItem`/`LineHistoryPage` plus mode/query types, including `recordType`, `gameDate`, `gameLink`, distinct original/stored/received/interpreted clocks, safe source URL/text/units, `coverage:'unknown'`, `correctionHistory:'unverified'`, skipped/scanned-record counts and next cursor. No raw payload, provenance, aliases, private evidence, active-unit selection or version collapse. Links require resolved provenance with the exact original ID and exclude reserved anonymous handles.
- Game mode reads at most 201 games for the exact team/date range; over 200 returns 400 asking for narrower dates. It then queries immutable claims for exactly those game IDs, at most 51 rows. Admission requires matching indexed identities/game/team/date/schedule, eligible claim shape, audited binding/phase spans matching source text, explicit supported game/date/opponent binding reasons, resolved original author/URL/ID/clock, publication evidence and identity-at-event evidence. Practice/camp are excluded from this stream. Missing admission evidence is counted as skipped, not promoted by a legacy game ID. Correction/retraction kinds remain visible as reports; the backend does not certify their complete chain or current effect.
- Publication mode reads at most 51 private report rows using team/date scope and `created_at<=asOf`, preserving all versions. A legacy game ID is always unverified and has no asserted game date; no ID is unlinked. Known original publication must match the indexed Eastern date; mismatches/malformed records are skipped visibly. Unknown original clocks remain null, with the best-effort stored clock separate. For canonical claims, `storedPublishedAt` carries the separately retained relay-publication clock.
- Canonical publication mode scans one exact existing `(team_id,game_id,interpreted_at,claim_id)` index prefix at a time, NULL-game bucket first, then one bound game ID per page. At most 51 candidate rows plus one next-ID discovery row are returned per request; no JSON publication-date predicate, global PK walk or new migration. Original clocks normalize to Eastern dates in JS. Valid out-of-range records are filtered, not counted skipped; unknown/malformed original clocks are skipped. Practice, rejected and partial interpretations can appear without meeting game-link admission. Game date remains null and game ID unverified/unlinked. Full historical publication browsing can require many explicit pages; zero-match pages retain progress/cursors.
- Each stream consumes at most 50 candidate records per page (`scannedRecords`), with row 51 only lookahead. Cursor binds mode/team/date range/snapshot and advances past filtered/skipped records; allowlisted keys/strict dates/timestamps are validated before PostgREST filters. Keyset order: legacy report date/key descending; game claims interpreted time/ID descending; publication claims interpreted time/ID ascending within one index prefix, with explicit next-prefix stage. Offset/microsecond database timestamps retain raw precision in cursor boundaries. No live-game service, observation, provider, ingestion or external request is invoked.
- Checks: **42 focused tests passed** (28 reader + 14 API), own-file ESLint **passed with zero warnings**. Initial pagination tests caught/fixed a cursor-field-count validation error. No broad tsc, build, browser or remote validation by this worker; Chef owns integration/typecheck.
- Optional offline real-data check: Chef's sanitized two-row VGK Nov 8 sample initially returned **0 accepted / 2 skipped / 0 links**, because SQL transport serialized top-level timestamp columns with a space separator/short UTC offset. An in-memory conversion of those three DB columns to PostgREST-style ISO timestamps returned **2 accepted / 0 skipped / 2 links**, one distinct parser version (`2026-11-06.1`). No raw text was printed and no app/test files changed. This verifies the DTO reader against the captured payloads with transport normalization, not a live PostgREST request or current link reachability.
- Limits: these are conservative source streams, not a complete historical correction archive. Canonical publication browsing is a paginated scan, not an indexed original-publication lookup; unknown-original-clock claims cannot be asserted in a publication range. `created_at` anchors exclude new legacy backfills across pages but cannot freeze mutable report updates. Immutable claims use interpretation-time anchors, not a separate creation-time snapshot; backdated later inserts are not frozen. Game scheduling changes between requests are revalidated, not transactionally snapshotted. Actual retained coverage, physical query plans and reachable source links are not inferred from local tests.
