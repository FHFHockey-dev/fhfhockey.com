## 3. Findings, ranked

1. **R12's "today + tomorrow" cannot deliver tomorrow.** `update-goalie-projections-v2` reads games `.gte(resumeDate).lte(today)` and `limit` slices *past* dates (`:98-150`); it never writes future rows, and no other job does (Q4: 0 rows for 10-22). The `goalie_start_priors_v2` gate (`run-projection-v2.ts:716-727`) therefore FAILs for `date=tomorrow`, the step is recorded `skipped` (`run-rolling-forge-pipeline.ts:968-974`) and the stage completes. The repair diary's "limit=7 covers 7 days ahead" was mistaken. *Coverage; affects every idle-tomorrow team.*
2. **The NST hole 10-07..10-18 (ES/PP/5v5) is the dominant accuracy input loss right now.** Every ev/pp rolling metric except PP goals/points has no WGO fallback (`rollingPlayerSourceSelection.ts:46-161`), so last-5 windows for those dates are thin or zero for shots, goals, assists, points, hits, blocks, PP heads, ixG and all on-ice metrics. FORGE's conversion pairs come from these. Going forward the pipeline's 20-URL step covers run−1 (10-20 complete), so the hole decays as windows roll past it (~5 games ≈ 10 days) unless backfilled. Job 79 (6 URLs/day vs 20 needed) can never clear it and fails daily.
3. **Reader run selection is horizon-blind while an unread h5 writer runs inside the window.** `requireLatestSucceededRunId`, Start Chart and the bridge pick the newest succeeded run for a date, then filter rows to `horizon_games=1`; an h5 run that is newest yields **zero skater rows for every team that day**. Normal days are safe only because the h1 run is created later; any manual h1 run before 10:12Z, or a pipeline failure, triggers it. The h5 job also serializes against the pipeline's h1 run via the same-date lease (409 → 207 `run_in_progress_elsewhere`) and failed 5 of the last 7 days. Nothing consumes h5 rows.
4. **Conversion is shrunk twice; shots once.** `computeSupportedStrengthSplitConversionRates` already shrinks toward an adaptive prior (priorStrength 12–72 shots); `skater-stage.ts:2186-2200` then shrinks the result again toward 0.095/0.145 by the window-blind F3 `sampleWeight` (≈0.7 for any veteran). A 13% shooter with 400 shots persists at ≈11.6–12%. Assists = goals × rate inherit it, so G, A and PPP are all compressed for the players who matter most. *Accuracy; G/A/PPP.*
5. **Thin windows raw + team reconciliation = Larkin/Wood.** `toi_seconds_avg_last5` and `sog_per_60_last5` are used raw (a 1-NST-game window counts like 5), then `reconcileFloatTotalByWeight` scales the whole team to L10 official shots with no clamp, so inflated thin-window players take a larger share and stable players a smaller one; conversion is not re-derived after reconciliation. Code-level mechanism with a fixture to confirm (w3 §2); not verified on rows.
6. **Same effect, several owners.** xGF enters shot, goal and assist environment; opponent goaltending enters as team 5v5 SV% (×2.3) *and* opp-goalie GSAA; rest multiplies TOI, shot rate, goal rate and assist rate; the `fantasy_score` trend multiplies shots, goal rate and assist rate; goalie `contextPct` raises SA and lowers SV%; the starter prior re-adds L10 share/season pct that `goalie_start_projections` already encodes. F8 named this; the inventory in w3 §1 makes it concrete. Skater rest: B2B = 1 lands on the mild 0.035 tier; the 0.11 tier is unreachable.
7. **Rolling table health.** Never analyzed, planner stats off by ~10× on the only predicate every reader uses (newest dates); autovacuum thresholds need ~200 days at 1,980 rows/day. 492 unread columns; 176 of the 381 physically stored (~45% of heap bytes, ≈2.5–3 GB est.); the sidecar carries 733 keys per row *including nulls* (~27 KB raw). FORGE reads ~80× the rows it keeps (`fetchRollingRows` 365-day span + whole sidecar, caller keeps the latest row per player, `skater-stage.ts:1469-1498`). `idx_rpgm_player_date` duplicates the PK prefix.
8. **Rolling writer correctness.** `season=` runs truncate `_all/_3ya/_career` (`:3031-3035` + `:2963`); `expected_sh_pct` at `all` strength adds WGO shots with 0 xG when NST is missing (`:1362-1369`); appearance-mode slots zero 22 metrics on NST gaps (hits/blocks root cause, generalized); 10-15 and 10-19 rolling rows are incomplete and nothing revisits past dates.
9. **The bridge's stale rule fires before the own-game lookup** (`forgeDailyBridge.ts:354` vs `:364`): a skater projected for today by today's run is dropped when his team's newer (tomorrow's) run omits him. Low frequency today; grows once finding 1 is fixed. Eight of the twelve coverage rungs are silent (no limitation line).
10. **Null heads (F6/A-08) are an octoberBranch-only behavior.** `6e14053ff` is not an ancestor of `origin/master`; the 10-21 master runs show 0/140 withheld heads with complete NST. The ~35% figure came from local octoberBranch runs. The latent consequence on the branch is large: team GF → null → goalie `proj_win_prob` null (W = 4 pts) whenever one skater row has a null head. Decide the head policy before any release that carries `6e14053ff`.
11. **Accuracy loop exists but measures the wrong thing, unsafely.** It scores raw h1 rows (not the bridge's re-aimed/blended lines the RSO shows), zero-fills null shutout/hits/blocks and fallback wins, has no naive control (`holdout_baselines` has no production writer), and the RPC's "latest succeeded" check ignores the git_sha fence. `forge/accuracy.ts` 500s on an empty series.
12. **Duplicate and wasted scheduled work.** Job 278 (14-day rolling, dies mid-list, leaves partial dates), job 393 (h5), job 79 (6-URL NST, failing), goalie step repeated per invocation, `nst_team_all` refreshed after FORGE reads it, `stopOnFailure=false` echoed as `true`. Estimated daily function time (w4 §2): pipeline ≈ 900–1,150 s over 6 productive slots + 278 ≈ 220 s + 393 ≈ 70–200 s + accuracy ≈ 137 s.

Corrections to earlier notes: accuracy *is* scheduled (pg_cron 361, not the Vercel step); `local:unknown` stamping is already in R12 (`run-lifecycle-queries.ts:248-250`); the "8 MB" sidecar figure excluded TOAST (611 MB total); line/PP context is complete.
