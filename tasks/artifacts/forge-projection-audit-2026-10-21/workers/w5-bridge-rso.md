## 2. Re-aim mechanics

### Skaters (:362–375)
1. **Own-game row wins** (R12): `exactSkater.get(game:player)` from a run that projected this game, same team → emitted as issued, no re-aim (:364–369). If that row is unknown-head it falls through to the re-aimed latest line (:368–370).
2. Otherwise the latest line is copied; for `row.game_id !== game.id` three multipliers apply (`retargetSkater`, :165–178):
   - **Team strength** `scale = (1 + facing.goalsFor) / (1 + projectedAgainst.goalsFor)` (:371–372). `goalsFor` = `computeTeamStrengthContextAdjustment({defending: opponent, opponent: own}).opponentGoalsForPctAdjustment` = `clamp((ownOffenseEdge·0.28 + oppDefenseLiability·0.22)·sampleWeight, ±TEAM_XG_WIN_CONTEXT_MAX_PCT)`, edges `clamp((xG/g − baseline)/baseline, ±0.2)`, `sampleWeight = clamp((xga_own + xga_opp)/280, 0, 1)` (`lib/projections/calculators/team-context-adjustments.ts:30–93`; bridge call :320–328). **One scalar** multiplies GOALS, PP/SH goals, GWG, ASSISTS, PP/SH assists and SOG alike (:169–171); HITS/BLK/TOI untouched by it (:172).
   - **Rest/home** `restScale` = ratio of `computeSkaterRestScheduleAdjustments(to)/(from)` multipliers (toi, shot, goal, assist) (:152–157). Goals get `team·r.goal·r.toi·tilt`, assists `team·r.assist·r.toi·tilt`, SOG `team·r.shot·r.toi·tilt`, HITS/BLK/TOI `r.toi` (:169–172). Formula: `teamRest<=0 → 0.11`, `=1 → 0.035` fatigue; recovery `>=3 → 0.03`, `=2 → 0.012`; opp fatigue `0.055/0.018`; home `+0.012` / away `−0.004`; `restDelta = clamp((team−opp)/3, ±1)`; clamped to `SKATER_REST_*_MIN/MAX` (`lib/projections/calculators/skater-adjustments.ts:348–393`).
   - **Rest-day convention**: bridge `restDays` = calendar days between the game date and the team's previous `games` date (:308–311); FORGE `fetchTeamRestDays` = days between `asOfDate` and the last game `< asOfDate` (`lib/projections/queries/team-context-queries.ts:456–473`). Both give **yesterday → 1** (B2B = 1), so the `<= 0` branch is unreachable in both; the ratio is coherent. FORGE's rest multipliers are applied in `skater-stage.ts:1843–1848` with the same function, so dividing them out is exact when both schedules agree.
   - **Opponent position tilt** `opponentTilts` (:105–138): per opponent, D share of points (and shots) allowed vs the league mean share; factor `1 + (own/base − 1)·g/(g+30)`, last season weighted as 20 games, clamp **[0.85, 1.15]**; F takes the mirror image so team totals are unchanged. `tiltBetween` applies `to/from` for the player's group (D if any eligible position is D) (:297–301). Applied to goals/assists (points) and SOG (shots) (:169–171).
3. **Stacking / double application.** FORGE's source line already contains `computeSkaterTeamLevelContextAdjustments` (`skater-adjustments.ts:225–299`): separate shot/goal/assist multipliers from `offenseEdge·0.14/0.16/0.18 + defenseLiabilityEdge·0.18/0.22/0.16 + paceEdge + pdoEdge (+ opponentSaveEdge·2.3 for goals)`, `sampleWeight` from xga/260 + 5v5 GP/18 + NST GP/40, edges clamped ±0.22; plus on-ice and opponent-goalie context (`skater-stage.ts:1795–1812, 2290–2312`). The bridge divides out a **different** estimate (`opponentGoalsForPctAdjustment`), so:
   - source game: `scale = 1`, `rest = null`, `tilt = undefined` → exactly as issued (correct);
   - later games: team-strength is re-aimed approximately (model mismatch; residual = FORGE's baked-in term ÷ bridge's estimate, both within ~±5 %); FORGE's **opponent-goalie and pace/PDO terms stay baked in from the source opponent** (not re-aimed at all); rest is re-aimed exactly; the tilt divides by the source opponent's tilt although FORGE never applied one (a modelling choice; ≤15 % either way).
   - Not a double count on the source game; a partial, mismatched re-aim on later games. Units are fractions; no new clamp on the composite product (`team·r.goal·r.toi·tilt` can compound to roughly ×0.75–×1.35 at the extremes).

### Goalies (:378–433)
- **Start shares**: `goalie_start_projections.l10_start_pct ?? season_start_pct`, newest `game_date|updated_at` per goalie in `[now−7d, now+1d]` (:286–292, :485–487). Exact FORGE row for the game → its `starter_probability`; the others split `1 − p` by share (:381–387). Without one: shares normalized by `max(1, mass)` (:389–391) — when shares sum below 1 the remainder is **unassigned**, not redistributed. Second night of a B2B (no exact row): the top goalie keeps `0.55` of his share, the rest moves to the others (:393–400). Accepted IFTTT news: confirmed → 1 / others 0; ruled out → 0, others rescaled; likely/projected floors 0.8 / 0.65 (:401–416).
- **Per-start line** source: exact row if his, else his own latest, else the team's latest goalie row (:420). Re-aim `retargetGoalieLine` (:180–189): `shots = (1+to.SA)/(1+from.SA)·(1+venue.to)/(1+venue.from)`, `against` likewise with the goals-against term, `win = clamp(W·(1+edge), 0.02, 0.98)` with `edge = (GF−GA)_to − (GF−GA)_from`, `SHO = min(1, SHO/against)`. Venue/rest via `goalieShotContext` (:159–163) with the goalie stage's constants (opp rested +0.03, opp B2B −0.04, own B2B +0.02, home −0.01 / away +0.02; clamp [−0.15, 0.2]) — the goalie stage applies those same constants (`goalie-stage.ts:335–336`) and the same `computeTeamStrengthContextAdjustment` (`goalie-stage.ts:212`), so the goalie re-aim is coherent with its source.
- **Saves/GA coherence**: SAVES and SHOTS_AGAINST scale by `shots`, GA by `against`; after re-aim `SAVES + GA ≠ SHOTS_AGAINST` by a few percent; nothing re-derives one from the others.
- **xG win estimate** `teamWinProbability` (:139–150), used when FORGE's `proj_win_prob` is null (common: `goalie-starter.ts:50` nulls the blend when any component lacks it): `scored = (own xGF/g + opp xGA/g)/2 · venue`, `allowed = (opp xGF/g + own xGA/g)/2 / venue`, `venue = 1.04 home / 0.96 away`; independent Poisson 0–12; `P(win) + P(tie)/2`; clamp [0.05, 0.95]; 0.5 if a prior is missing. Team-only: ignores the goalie's own quality and the opposing starter. `LOSSES = 1 − win` (no OTL split). Counted (:450).
- **Priors** `teamStrengthPriors` (:73–102): `nhl_team_data` latest-date row whose `xga/xga_per_game ≈ games_played` (exactly one match required, else no prior); last season (`nst_team_stats`, situation all) blended as 20 games.
- Emitted stats = per-start line × p (unconditional); `conditionalStats` = the per-start line; `startProbability = p`; `confirmedStart` only on IFTTT confirmed (:431–432).

## 3. Admission into RSO planning: forecast → per-game points

- **League weights**: Yahoo `settings.scoringCategories` (keys via `YAHOO_STAT_KEY_BY_ID`, `lib/integrations/yahoo/liveDraft.ts:275–304`) → `rules.scoring.weights` (`lib/integrations/yahoo/rosterPlanning.ts:424`). - **Per play**: `playValue` (`lib/rosterScheduleOptimizer/planning.ts:244–251`): for every weight ≠ 0 that `applies` to the player's class, requires `forecastAllows(…, "assignment")` and a finite `assignmentStats[key]`; **any one missing → the play's value is null**. `applies` (:86–98): goalie stats only to goalies; a key applies to a class if any forecast of that class has it finite, or if no forecast of either class has it (so a league key no bridge row carries, e.g. an unknown category, still applies and nulls everyone).
- **Per lineup**: unknown plays contaminate every competing play that shares a compatible slot (UTIL links all skaters) (:371–385) and are assigned by schedule capacity (:412–418). `projectedValue` is null when any selected play lacks a forecast or any needed key is non-finite (:853); `comparisonEligible` requires zero `unresolved` (:897, :927). `playerAssignedPoints` returns null for **every** player when `comparisonEligible` is false or `projectedValue` null (:107–110). The ledger's `projectedPoints` (`contributionLedger.ts:99`) and the DROP chip (`lineupGaps.ts:55–63`, `retention.ts:46–47, 71–75`) inherit that. **Confirmed: one missing forecast → every player's lineup points unknown**, and `unprojectedDrops` names the players lacking a forecast (`lineupGaps.ts:58–61`).
- **Where a partial-known sum could be shown with a flag** (display only, never for ranking — repository policy "unknown is not zero"):
  1. `playerAssignedPoints` (:107–128) — return `{ value, missing: string[] }` summing known keys of the player's own assignments; the planner's objective keeps using the strict null.
  2. `PlanEvaluation.projectedStats` already carries per-key sums and emits `Projected ${key} is incomplete` (:845); a "known-part points" line could be derived from it.
  3. `contributionLedger.projectedPoints` → `knownProjectedPoints` + `missingTargets` on `PlayerContribution` (`contributionLedger.ts:15–22`).
  4. `lineupGapReport.bestDrop.projectedPoints` (`lineupGaps.ts:63`) — flagged partial value beside the "no projection" badge.
- **Freshness**: bridge `cutoffAt = issuedAt = forge_runs.created_at`, `expiresAt = min(game start, +8 d)` (:336, :338). `resolvePlanningContributions` rejects `issued > asOf`, `expiry ≤ asOf`, `revisionId ∉ manifest.issuedRevisionIds` (`planningContributions.ts:68–77`). `refreshForecastInputs` (`lib/rosterScheduleOptimizer/refreshForecastInputs.ts:7–30`) replaces forecasts/baselines/manifest and moves `context.asOf` to `checkedAt` only if the shared manifest is not older than the snapshot and `checkedAt ≥ manifest.asOf`; schedule evidence is kept (R5 gap, documented). ## 5. Native path vs bridge (brief)

- `selectForecastServingSource` (`lib/player-forecasts/forecastServingSource.ts:59–79`): with `PLAYER_FORECAST_NATIVE_CATALOG_HEAD_ID` set the result is `native`, or `legacy_flagged`/`empty` when the head is unusable (`:21–26`) — **never `legacy`**. `planning.ts:181` runs the bridge only for `source.kind === "legacy"`, so setting the head id (even to an expired/invalid head) switches the bridge off; with an empty native catalog the RSO becomes schedule-only.
- **Contract**: native supplies `baselineSources` (`ContributionSource`: per-target `mean`, `basis per_appearance|per_start`, `participationIntegrated false`, `allowedUses`, `catalogExpiresAt`; `contributions.ts:48–76`) and `participationSources` (`ContributionParticipation` with hashed model receipts, `:78–108`). `resolveContribution` (`:267–368`) gives `unconditional = mean × participation probability`, blends with any detailed row by calendar overlap weight (`:306–318`), and denies uses when participation is missing (`:331`). The bridge instead emits `detailed` rows with `basis unconditional_game`, `participationIntegrated true` (`planningContributions.ts:189–190`) — skater appearance probability is implicitly 1 (injury handled only by the stale rule); goalies carry `startProbability`.
- **By design**: native = per-target means (rolling/season rates) with explicit, revisioned appearance/start participation for every catalogued player regardless of dressing in the last game (coverage up; no opponent/rest/home context — `baselinePolicy.ts` per F8); bridge = per-game, opponent-aware FORGE lines for the 18 who dressed, re-aimed approximately, participation implicit. `gameExpectations.ts:11–12` targets include PENALTY_MINUTES/TOI and WINS/SHUTOUTS for goalies, so TJ's ten keys are all representable.
