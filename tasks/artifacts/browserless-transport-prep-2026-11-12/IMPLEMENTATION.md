## Candidate behavior

- `web/lib/lines/browserlessTransport.ts` parses the server-owned endpoint before allocating a socket. It accepts only explicit `wss://` URLs with a host, without credentials in userinfo, fragments, control/space characters, backslashes or missing authority. Rejections have a fixed message and contain no input URL. The Browserless token remains in the configured query string; no production token was read or generated.
- The adapter uses `ws` with `followRedirects: false` and `rejectUnauthorized: true`. All HTTP non-upgrade responses close the attempt, including redirects to another host or plaintext transport. It preserves Puppeteer's `allowSynchronousEvents: false`, payload/compression options and versioned User-Agent. There is no endpoint fallback, certificate bypass or reconnect. The initial configured host is trusted server configuration; there is no separate hardcoded hostname/allowlist because the future approved TLS host is not known. Request parameters never supply the endpoint. Protecting the selected configuration and its DNS remains an operator gate.
- A 10-second outer deadline bounds DNS/connection/upgrade waiting; the WebSocket handshake also uses a 10-second timeout. Failure terminates the owned socket, cancels the deadline, and rejects with a fixed error plus the existing allowlisted diagnostic as its cause. Constructor, handshake and synchronous send errors cannot carry their raw objects across this boundary. Established errors close the transport without forwarding the raw error. Closure is idempotent.
- The route passes only `{ transport }` to `puppeteer.connect`, avoiding Puppeteer's stock redirect-following transport. If CDP connection setup fails after the socket opens, it closes that transport before the existing sanitized failure logging and nonretryable response. A `finally` also releases the owned transport after capture success or failure, before a screenshot retry. Existing screenshot/Discord behavior and matrix selector are preserved.
- `webhookErrorDiagnostic` adds only two fixed reason mappings: `endpoint_invalid_or_insecure` and `browser_transport_failed`. Its field/code/status allowlists and recursion limits are unchanged.
