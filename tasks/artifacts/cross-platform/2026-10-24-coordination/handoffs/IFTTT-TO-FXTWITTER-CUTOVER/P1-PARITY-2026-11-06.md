# P1 parity replay: IFTTT input vs FxTwitter input (2026-11-06)

- **Ran:** 2026-11-06 at 18:15 UTC, read-only, using `web/scripts/x-timeline-parity-replay.ts`. Nothing was written to the database.
- **Window:** IFTTT queue rows received since 2026-11-06 01:30 UTC (the shadow's first run was at 01:32), compared against every `x_timeline_shadow_posts` row for the 6 line-queue accounts. FHFHockey is excluded because it feeds `social_share_x_posts`, not a line queue.
- **Raw results:** `P1-PARITY-2026-11-06.json`, in this folder. It has one record per pair, plus the unpaired rows.

## Method

1. **Pairing.**
   - Own posts and quotes are paired by `(source_key, tweet_id)`.
   - Reposts have to be paired another way, because IFTTT keys them by the wrapper's id and the shadow by the original's. They are paired by the `RT @handle` prefix plus the first 40 characters of the text, with URLs and whitespace normalised.
2. **Parsing.** Each pair goes through the same parser twice, once with the IFTTT row's `text` and once with `toQueueRow(shadow).text`. The parser is the swipe trainer's replay (`parseTweetForTrainer` → `buildLinesCccSourceFromIftttEvent`), with `TWEET_PIPELINE_INTERPRETATION_ENABLED=true` as in production, and with the same season rosters (learned aliases included).
3. **Extraction comparison.** The two parses are compared with `compareExtraction`: type, category and subcategory, the matched players, the forward lines, D pairs and goalies, and the extras.
4. **Attribution.** `tweetClaimAttribution` runs on each row as the processors would build it.
5. **Quotes.** `quotedTweetFromFxtwitterPayload` checks whether the scraper row carries its quoted post.

## What this shows

- **The scraper's text is a safe drop-in for parsing.** Every paired post gave the same extraction on both inputs, across all 6 queue accounts.
- **Repost attribution is the clear gain.** Under IFTTT, no repost is credited to its original author: the `RT @` wrapper blocks it, and IFTTT never sends the v2 payload. With the scraper's v2 payload, every repost is credited.
- **Quotes no longer need the `t.co` → oEmbed round trip.** That removes a network lookup per quote and a failure mode with it.
- **Coverage:** the only post IFTTT had that the scraper missed is a reply to another account. That gap matters most for CCC (§6.7 of the debrief), so probe it before CCC switches.

## What this does not cover

- **Not the full processor run.** It skips oEmbed enrichment, the processor's quote-preference and wrapper-rejection steps, snapshot writing and forecasts. In production, a repost's `link_to_tweet` is now the original's URL, so oEmbed enrichment of it should succeed where the wrapper URL failed. If the enriched text differs from `full_text` after URLs and whitespace are normalised, though, attribution's text-equality check could fail. **Check this first in the P2 canary.**
- **Timing and coverage come from the 2026-11-06 coverage read and the 2026-11-08 scheduled check,** not from this replay.
- **This is one window,** about 17 hours on a weekday, with 79 IFTTT rows. Rerun the script before each account switches (P3–P5).
