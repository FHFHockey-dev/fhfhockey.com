# Goalie checkpoint RPC contract — local implementation

Current source: `supabase/migrations/20261101161622_nst_goalie_catchup_v1.sql`, generated by Supabase CLI after the conflict-free allocation in `SQL-ALLOCATION.json`. `schema-design.sql` is the retained earlier design, superseded by the canonical migration. No hosted migration or activation has occurred.

The migration creates eight service-only tables: cohorts, units, cohort membership, daily budgets, claims, unit receipts, disabled control, and final-day evidence. Six adapter RPCs plus one day-evidence verifier are SECURITY INVOKER with fixed search paths. RLS is enabled; PUBLIC/anon/authenticated have neither table nor function access. The runtime role can read but cannot enable control or write finality evidence. Its column grant on `control.singleton` permits the serialization row lock, not activation.

| RPC | Current implementation |
|---|---|
| `nst_goalie_ensure_cohort_v1(p_manifest)` | Locks the control row; validates the complete ordered ten-dataset/date aperture, immutable original plan, persisted final-day evidence and current WGO/game keys. Preserves existing units/holds and refuses source-version replacement. Cohort creation and one runner enqueue commit together; matching duplicate returns the same job. No fabricated complete/no-games state is accepted. |
| `nst_goalie_read_state_v1(p_scope)` | Returns at most140units plus the original request count, current UTC budget, explicit clearance/cooldown and global review state. Missing/expired clearance is occupied/unknown. Expired or held claims remain review-required across days and cohorts. |
| `nst_goalie_claim_step_v1(p_scope,p_unit_keys,p_max_attempts,p_deadline_at)` | Serializes against ensure/other claims, checks DB time/windows, explicit exclusive clearance, ten-minute direct-job cooldown, oldest pending ordered units, max20burst/6strict, seven steps and60reserved attempts/day. Atomically reserves before provider dispatch. No automatic claim expiry/replay. |
| `nst_goalie_commit_unit_v1(p_scope,p_claim_id,p_unit_key,p_rows,p_source_fingerprint,p_validated_empty,p_parsed_rows,p_mapped_rows)` | Live claim, max100rows, one-game grain, key uniqueness/date/season, known columns and required core fields. Selects output from a fixed ten-table map. AllCounts/allRates require the exact attested WGO identities; special situations may be subsets. Revalidates finality/WGO evidence; output plus receipt commit together. Stored identities must equal parsed identities, so unexplained pre-existing extras or invalid empty results roll back. Consistent duplicate is idempotent. |
| `nst_goalie_finish_step_v1(p_scope,p_claim_id,p_attempts_used,p_committed_unit_keys)` | Verifies ordered durable receipts and bounded reported attempts; records finish and releases unstarted units. **No reservation refund.** Reply adds `attemptsCharged=attemptsReserved`, `unusedReleased=0`. Matching settlement is idempotent; expired/held claims require review. |
| `nst_goalie_hold_step_v1(p_scope,p_claim_id,p_reason)` | Persists a global review hold; keeps uncertain reservation charged. Already committed receipts remain. An uncertain finish acknowledgement also produces a durable unit review hold; no replay is inferred. |

`nst_goalie_verify_day_v1` requires a stored finality attestation and checks that its sorted game/goalie IDs still match the bounded day in `games` and positive WGO appearances; every game requires at least two distinct goalie appearances, each with a game ID and games_played=1. The attestation is a prerequisite, **not generated from those checks**: `games.date` and WGO row presence do not independently establish finality. Unknown evidence rejects ensure/commit.

The explicit `catchupScope=<sha256>` route branch now imports the adapter. It fetches/parses/maps only, using the guarded client and immutable full-job request count. Empty results need complete headers; malformed numeric/core fields and ambiguous exact names hold the claim. The source callback does not write output. The RPC owns the upsert. The runner preserves exactly the same checkpoint scope and existing audit/uncertain-write fences. Legacy query modes still use their guarded cursor path and its old completeness heuristic.

Source work stops before the final20seconds; no new source starts without35seconds headroom. RPC waits are bounded to5seconds. A lost acknowledgement cannot establish rollback. The shared client does not expose a claim-aware abort/accounting hook; uncertainty remains held, and reservations are never refunded on the client counter alone.

## Deliberate remaining gates

1. Implement/allocate a trusted final-game evidence producer and bounded current-season cohort preparer. No automatic caller currently populates `nst_goalie_day_evidence` or invokes ensure daily. Runtime has no grant to manufacture evidence.
2. Integrate an acknowledged exclusive shared-NST lifecycle. Control is disabled by default; no existing producer currently writes its clearance. Admission timestamps enforce request windows but cannot prove a direct job ended or prevent its next invocation. Clearance requires coordination with all participating jobs and operator-approved schedule ownership before activation.
3. No verified actual-attempt refund is implemented. Strict six-unit steps reserve18; the tested maximum is24successful units/day at reservations18+18+18+6. Small cohorts can reserve60 for20units and stop for that day. These are healthy bounds, not observed production throughput; runtime/deadlines/retries/holds may reduce them. Earlier hypothetical42/day assumed refunds and is superseded.
4. Wire durable per-dataset hold/progress and two-window no-progress reporting. Existing allCounts freshness reporting remains useful and unchanged.
5. Keep shared-admission prerequisite installation first, checkpoint migration disabled second, reviewed app deployment third, verified lifecycle/evidence wiring and separately approved schedule/enable changes last. No production operation follows from local SQL allocation.
