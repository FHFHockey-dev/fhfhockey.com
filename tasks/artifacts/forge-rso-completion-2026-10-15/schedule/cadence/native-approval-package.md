## Exact SQL review artifact

native-cadence-proposal.sql is NOT applied or a source-authorized migration. It is independent of the seasonal SQL proposal. It adds **cadence_slots JSONB** to public.forge_game_update_queue, adds **public.enqueue_forge_cadence_slot** and a pure internal metadata transition helper, and replaces existing **claim_starter_board_jobs / finish_starter_board_job** bodies with scoped cadence bookkeeping. Existing service-role/RLS boundaries remain. New function execute is revoked from PUBLIC/anon/authenticated and granted only to service_role. No scheduler registration or inference flags.

The enqueue RPC verifies current game start against the declared start/date under a game-row share lock, derives 08:00 New York or start minus15min, requires the current local day and a future unstarted game, validates explicit source completion counts/revisions, and rejects early/incomplete inputs. A nonblocking per-game advisory lock and existing queue-row serialization make duplicate coordinators return deduplicated or busy-held, without advancing versions for an existing slot. New slots use the existing native enqueue function and queue fencing, with immediate cadence not_before. Per-row history is capped at eight slots, source JSON at64KiB, and new enqueue lock wait at1s. No source/provider call occurs under locks.

Each slot retains due time, actual accepted time, late flag, source receipts, schedule start, requested queue version, status and attempt count. Successful finish attaches the immutable actual revision/run/decision/publication references. Successful/superseded receipts never change. Failed receipts at three attempts remain terminal, even if later independent legacy news succeeds; a later revision cannot silently certify an exhausted earlier slot. Other uncompleted old versions become superseded(newer_queue_version), without spending their attempts. Changed schedules supersede old unsatisfied slots rather than crediting mismatched games. A new rescheduled news slot has a distinct start-based key.

Claims count only the matching active cadence version and cap its attempts at three, while preserving ordinary later news processing. Expired running cadence claims first reconcile any already-published immutable revision for their active_run_id, up to p_limit rows under SKIP LOCKED, avoiding recomputation after a lost finish acknowledgement. Otherwise existing fenced lease handling applies. Separate morning and later revisions therefore retain honest history and missingness.
