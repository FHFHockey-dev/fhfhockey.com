# Offline bundle contract

`fixtures.py` is an executable example of `f6-ledger-week-v1`. All example IDs, timestamps, rows and proof references are synthetic. They are not real first-issuance receipts. Never copy synthetic proof flags into a real export. Normalize timestamps to the same UTC ISO representation with explicit offset and preserve all source precision. Preserve numeric zeros and nulls. Resolve decimal strings to numeric JSON only when the exporter actually typed the value as numeric; do not coerce arbitrary strings or booleans.

The evaluator reads one local UTF-8 JSON file, at most 50 MB, and emits its report to stdout. It does not fetch, normalize, or invent remote evidence. A reviewer assembles a real bundle from approved raw exports plus retained external proofs before evaluation. This manual evidence assembly is deliberate: the seven SELECTs do not contain all the prerequisites.

| Member | Required origin and fields |
|---|---|
| `schema_version` | Literal `f6-ledger-week-v1`. |
| `meta` | `synthetic` boolean; fixed Release C `release_sha`; `season_id`; approved `from_date`, `to_date`; `observed_at`; `complete_export: true`; `truncated: false`; immutable `export_receipt_ref`; exact `row_counts` for every array below. The exporter must retain all seven raw results, no sentinel overflow or transport truncation, and the transaction observation time. |
| `runs` | Query 1 rows: `run_id`, `as_of_date`, full 40-character `git_sha`, `status`, `created_at`; do not collapse multiple successful runs on one date. Unknown/short/local SHAs cannot qualify a baseline cohort. |
| `ledger` | Query 2 rows using actual ledger column names. Do not prefilter unknown participation, missing categories or unsettled rows. Sources absent entirely are reported as unavailable controls, not synthesized. Do not replace ledger expected heads with Q6 rows. |
| `projections` | Query 3 rows: exact run/game/player/horizon identity, date/team, `created_at`, `updated_at`, ES+PP G/A/SOG, HIT/BLK. No PK/SH augmentation; preserve Release C accounting. All runs appear in Q6 diagnostics; only exact served-run joins enter the primary dressed Q6 checks. |
| `rolling` | Query 4 EV rows using original column names, including update timestamps. Current-state diagnostics only; NULL and zero stay different. No issue-time or model-SHA attribution. |
| `calendar` | Ordered list for **every** calendar date in the requested window: `date`, exact `game_ids`, `complete: true`, `receipt_ref`. Derive membership from the approved complete query 5 export plus its coverage receipt. A zero-game date has `game_ids: []` and still needs the schedule receipt. |
| `games` | Query 5 identity mapped to `game_id`, `date`, `scheduled_at`, `team_ids: [home, away]`, with independent `final: true`, `final_at`, `skater_population_complete: true`, `receipt_ref`, `dressed_skater_ids_by_team: {"<team ID>": [player IDs]}` from trusted final complete ingestion/roster evidence. **The `games` DB schema does not supply finality.** Every team list must exactly match independent dressed universe rows. |
| `universe` | Independent season × served date × class × player × game rows. Each includes `team_id`, proved `dressed` boolean, `receipt_ref`, and actual scoring heads using ledger `act_*` names. All dressed players must be represented even when absent from all forecasts. Include independently proved non-dressed members needed by exported forecasts. Missing WGO rows cannot be converted to DNP. Optional `position_at_game: F/D/null` must come from historical evidence; C/LW/RW map to F only with that historical source. |
| `issuance` | One externally retained forecast-history receipt per ledger row: `key: [served_date, player_id, game_id, source]`, `served_at`, `complete_history: true`, `revision_count: 1`, `receipt_ref`, `forecast_sha256`. Hash the **retained issued forecast**, never generate a proof by hashing the current mutable DB row. `audit.fingerprint` defines canonical numeric JSON and forecast-only fields; settlement changes are excluded. Any overwritten/reissued forecast or absent history refuses. |
| `baseline_receipt` | `verified: true`, `git_sha`, `run_id`, `issued_at`, `served_at`, `first_served_date`, `receipt_ref`, `earlier_release_rows_checked: true`. Must bind the actual earliest served Release C issuance in retained evidence to query 1/run creation and query 2/issued row, and establish the pre-window lower-bound search. A deployment log or cron time is insufficient. |

Raw actuals from query 6 are normalized explicitly: `goals→act_goals`, `assists→act_assists`, `pp_points→act_pp_points`, `shots→act_shots`, `hits→act_hits`, `blocked_shots→act_blocks`. Use `team_abbrev` only with historical team identity evidence. Query 7 maps saves/goals_against/wins/shutouts to act_saves/act_goals_against/act_win/act_shutout; retain explicit started evidence. Missing categories stay null. Do not derive an absent player from someone else's actuals. Ledger and independent actuals must agree; late corrections require a new coherent approved export, not mixing old ledger and new actuals.

The primary baseline must have seven complete game-bearing dates starting at its verified first served date. Every calendar date is inspected in order, including gaps/no-game days. Exported data for another SHA remains separately visible, but a mixed primary exact cohort is refused. Native rows cannot inherit a SHA from their date. `bridge_reaimed` and goalie/control comparisons remain diagnostic, never substitute for the primary exact cohort.

Per-array caps: ledger/issuance 20,000; runs 500; h1 10,000; rolling 12,000; games 250; normalized universe 6,000. An array count mismatch, cap overflow, unknown identity, malformed/missing timestamp, incomplete history, invalid numeric head, or missing receipt returns `REFUSED`. Raw row caps in SQL include one additional sentinel each; **sentinel rows are evidence of overflow, not rows to discard to pass**.

A proof reference and `verified` flag are attestations from an independently reviewed acquisition, not cryptographic authentication. The offline evaluator verifies internal consistency and hashes; it cannot authenticate a forged external receipt or discover an omitted source row by itself. Never certify completeness solely by setting booleans or copying ledger membership. If finality/universe/revision proofs do not exist, deliver the refused report and escalate the evidence-contract gap to the ledger owner without changing their code.
