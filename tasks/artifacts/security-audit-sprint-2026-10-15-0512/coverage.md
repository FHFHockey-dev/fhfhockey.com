## Lower-priority observations, not confirmed exploitable findings

1. **Yahoo next-path canonicalization** — `web/lib/integrations/yahoo/oauth.ts:51` rejects `//` but not backslashes/control characters; `buildYahooAccountRedirect` later emits the path. The current UI sends a fixed next path and the initiation endpoint is authenticated/browser-bound, so a practical attacker-controlled navigation path was not established. Prefer the stricter Patreon sanitizer and add local slash/backslash/control-character tests.
2. **Query credential transport** — `web/lib/sources/lineSourceIftttReceiver.ts:36` permits `req.query.secret`. URLs may appear in upstream access logs. Prefer a dedicated header, with an intentional compatibility transition. No actual URL/credential was read, and no log leakage was verified.
3. **Browser defense headers** — no app-wide CSP or anti-framing policy is present in the reviewed source config. Platform-supplied headers may exist; check approved deployment metadata or a separately authorized bounded request before calling them missing in production. Introduce a compatible policy only after testing actual asset/script needs.
4. **Dependency reproducibility** — `functions/Pipfile` uses wildcard packages and no tracked `Pipfile.lock` exists; `functions/requirements.txt` pins top-level packages only. CMS/functions JavaScript lack a tracked lockfile. This is supply-chain/reproducibility exposure, not evidence of a particular CVE. No lock regeneration was attempted.
5. **Tracked environment filenames** — Git tracks `cms/.env.development`, `web/.env.development`, `web/.env.production`, and `web/.env.test`. Contents and values were deliberately not inspected, so their presence is not a secret-leak finding. An authorized name-only/config-ownership review can establish whether they are public configuration/examples without printing values.
