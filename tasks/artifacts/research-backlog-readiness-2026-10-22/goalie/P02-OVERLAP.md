## Participation and existing good behavior

`playerStatsContract.ts:94–99` correctly defines **appearance** as `games_played > 0`. The control fixture counts both a start and relief as two appearances. That definition should remain; QS requires an additional start/classification contract, not a change that erases relief appearances. This is the same boundary exposed by the main audit's GR-D3: workload start counts cannot be reconstructed merely from a goalie-game row's existence.

The shared SV helper correctly pools complete numerator/denominator pairs, returns .925 for 27/30 plus 10/10, and returns null for no usable pair or zero shot exposure. No arithmetic finding for those qualified inputs. Its current return value alone carries no coverage metadata; the consumer must not turn a supported-subset result into a full-window claim.

The contextual component deliberately concatenates regular/playoff logs (`:67–70`), while the overview passes a filtered regular log plus a playoff log. QS/SV comparisons therefore need explicit same-window/season/cohort admission, even when each arithmetic function is correct. This supplement does not prove every current combination is wrong, audit all playoff/trade joins, or reimplement the completed SOG contract. Stable game identity, team-at-game, source grain, finality and coverage remain prerequisites from that packet. Neither missing source rows nor current-team schedule membership establishes a historical absence or start.

## Relationship to the FORGE model

`fetchGoalieEvidence` independently reads `wgo_goalie_stats.quality_start,quality_starts_pct` (`goalie-queries.ts:284–291,336–356`). `computeGoalieProjectionModel` uses QS count as the weight `QS/(QS+16)` and the normalized rate relative to .53 for a stability adjustment (`goalieModel.ts:174–184,203–218`). It does **not** call the contextual component's QS/appearance calculation. Thus P02-D1 is not proof that this UI denominator contaminates FORGE.

No original QS classification algorithm, total classified starts, source version or per-row coverage is selected into that FORGE evidence object. Its weighting by successes rather than all classified starts is an existing calibration choice to qualify, not a demonstrated arithmetic bug. Preserve the current model; require compatible QS grain/coverage before stronger reliability claims. Similarly, `safeStdDev` returns zero for at most one residual (`utils/number-utils.ts:62–68`), so a low-sample stability label is not empirical reliability evidence. The main audit's D2 example explicitly has one row; do not interpret its zero residual SD as measured consistency.
