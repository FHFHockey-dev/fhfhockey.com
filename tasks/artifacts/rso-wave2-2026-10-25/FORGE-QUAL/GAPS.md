Paths are under `web/` unless noted. Every line citation was read in this checkout (`octoberBranch` at `0f8a09fff`). Severity is about qualifying a forecast for RSO and Start Chart use, not about product bugs in general.

## Significant: qualification evidence would be weak or ambiguous

| # | Gap | Evidence | Consequence |
|---|---|---|---|
| G5 | **Start Chart has no use gate.** Admission hard-codes `allowedUses {assignment, totals, comparison: true}` for every admitted row. Start Chart display is gated only by `STARTER_BOARD_SERVING_ENABLED` and the canary list. | `lib/projections/consumerRevisionAdmission.ts:121`; `pages/api/v1/start-chart.ts:929-943` | Qualification means different things in the two consumers: Start Chart *displays* whatever admission passes, while RSO needs a reviewed scope. | G6 | **There is no readback capture.** `forge-served-forecast-snapshot` recomputes **bridge** forecasts into `forge_served_forecast_ledger`. It doesn't record what either consumer served. | `pages/api/v1/db/forge-served-forecast-snapshot.ts:12-15`, `:55` | Readbacks have to be bounded consumer GETs captured at a stated time (plan §4). A dormant immutable table `forge_board_visibility_observations(revision_id, probe_id, observed_at)` exists, but no web code writes it (`supabase/migrations/20260916023000_starter_board_release_control.sql:19-25`; `rg` finds no caller). |
| G7 | **Start Chart rows on the revision path carry no revision id.** Each row has to be joined via `game_id` to `gameRevisions[]`. | `pages/api/v1/start-chart.ts:1643-1663` (rows), `:2126-2131` (`gameRevisions`) | The join is unambiguous only because the RPC returns one revision per game (`supabase/migrations/20261004181455_forge_public_revision_reader.sql:7-27`). | G8 | **The consumer value is recomputed, not stored.** Both consumers compute skater expectations from the frozen payload row via `completeBoardSkaterStatsFromProjection` + `boardSkaterForecast`. A row without participation is excluded as `missing_participation`, not served. | `lib/projections/consumerRevisionAdmission.ts:167-173`; Start Chart copies the admitted stats at `pages/api/v1/start-chart.ts:1647-1663` | The "issued value" must be defined as the repo's own admission output on the frozen row at the issuing code version. | G9 | **There is no parent or lineage check in admission.** `previousRevision` is display-only, and nothing checks a parent revision. | `supabase/migrations/20261004181455_forge_public_revision_reader.sql:16-21`; admission files (no parent check found) | Lineage evidence relies on the RPC precedence (frozen pregame row, then latest selection event, then latest by decision time), which the plan records per game. |
| G10 | **The native path has no code identity and doesn't persist horizon.** Native rows are content-addressed hashes (`definitionHash`, bundle `checksum`, `candidateInputHash`, `packageHash`) with no git sha. `NATIVE_DAILY_HORIZON = 20` only slices games. | `lib/player-forecasts/nativeDailyPipeline.ts:18`, `:147`; `lib/player-forecasts/contributionStore.ts:40-85` | Native qualification can bind method and artifact but not code. Not a blocker for the recommended first target (legacy detailed path). |
| G11 | **Native v2 frozen participation expires in two days.** `FROZEN_PARTICIPATION_LAST_CUTOFF = 2026-10-27T04:00Z`. After that `inputs-v2` throws `rolling_first_issuance_not_approved` unless `rollingFirstIssuance` is approved; all four v2 flags are off. | `lib/player-forecasts/nativeDailyPipelineV2.ts:16-30`, `:74-78` | It's time-bound but separate from the first target. Native daily issuance stops cleanly (it fails closed) unless TJ decides (DECISIONS D6). |
