# RSO UI pass: accessibility check (2026-10-29)

**Standard:** WCAG 2.1 AA. **Method:** the Design plugin's accessibility-review checklist, plus checks run by hand: computed contrast, tab order and focus rings, measured in Playwright against the fictional offline fixture at 1600 px and 390 px. Axe is parked until Monday, so no automated Axe scan ran.

**Scope:** the elements the six UI-pass steps added or changed.

## Summary

**Issues:** 1 that predates this pass (now fixed in step 7), plus 2 minor notes.

- **Pass:** every element below meets 4.5:1 contrast.
- **Focus:** each new control shows the 2 px focus outline.
- **Tab order** in the command bar is logical: provider chip, then Refresh, date range, Current week, search, the status rail (Data health), Matchup, Save to account and ☰. Undo is skipped while it is disabled.

## Notes

1. **Fixed in step 7 (predated the pass), 1.4.3:** DROP chip contrast went from 2.78:1 to 6.76:1 with dark text on the coral chip.
2. **Minor, 2.2.1:** success toasts fade after about 7 s and pause on hover, but not on keyboard focus (they are not focusable). Screen readers still hear them, because the live region (role `status`) stays in the DOM.
3. **Minor:** the ownership caution's tooltip (`title`) is mouse-only. Keyboard and screen-reader users get the full sentence in the player button's name; touch users see only the "?" marker.

## Touch targets (390 px)

- **Pass:** the new phone controls keep 40–44 px: Refresh, Current week and the date range at 40 px; sort, Find & filter and the confirm button at 44 px.
- **Unchanged:** Undo and Matchup stay at 30 px. An older `.navBar .commandActions button` rule set that before this pass. It is above the 24 px WCAG 2.2 minimum.
