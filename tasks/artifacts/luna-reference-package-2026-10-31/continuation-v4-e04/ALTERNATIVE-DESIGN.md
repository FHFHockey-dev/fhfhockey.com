# Optional coverage-first ordering — proposal only

Repeated early stops have limited diagnostic coverage: E01 omitted a goalie status; E02/E03 supplied the expected status but invalid coordinates. The separate binding-review candidate makes those errors inspectable, but does not turn the original grades into passes or authorize continuation.

The frozen executable plan in this directory retains **E04→E16 order and stop on the first original schema/label failure**. A mutually exclusive alternative for independent review is to reorder the same remaining reports into two fixed phases, with every existing validation, stop, budget and authority guard unchanged:

1. **Abstention/unsupported-context coverage:** E04, E05, E07, E08, E09, E12, E13, E14, E16 — nine Responses requests. These cover practice/warmup attendance, backup, conditional start, ambiguous identity, correction, historical scope, skater/PP context and unavailable identity.
2. **Positive wording/evidence coverage:** E06, E10, E11, E15 — four Responses and the existing three Decisions legs for E06/E10/E11, at most seven requests. These cover explicit warmup starter wording, injection, mixed subjects and Unicode likely wording.

This could collect broader diagnostic case coverage before another quote-offset failure. It does not guarantee any case passes and does not convert the material into a holdout. Results must retain individual case outcomes and phase denominators; a phase-selected pass rate is not overall model accuracy.

Both phases together use **the same 16 remaining calls**, not an additional allowance. The four consumed calls, historical reservation, $1 ceiling, zero retries, concurrency one and unchanged expiry carry forward. Every report must still pass its original grade before the next report; any uncertain/provider outcome stops immediately. Coordinate candidates stay separate and cannot clear that stop. The three Decisions legs remain conditional on their Responses leg validating, as in the existing caller.

No alternative dispatcher, relaxed validator, skipped failure, automatic resume, label replacement or correction-acceptance shortcut is proposed. No report is repeated. After any new paid result, this proposed order must be reduced to the still-uncalled reports and frozen against the resulting exact ledger before independent approval.

**This alternative is not selected or executable under `PLAN.json`.** Choosing it requires a new frozen request sequence, offline rehearsal and independent review before any paid execution. It must replace the primary plan, not run alongside it or create a second ledger. Until then, only the primary plan is a prepared review candidate, and the real ledger remains disabled.
