## 2. Player-card PRD inputs

### Accepted user steer

Each metric must contain **actual value + raw ordinal rank + valid-player denominator + percentile**. The default raw pool is **all NHL players with a valid value in the exact same period/strength state**. No minimum-TOI/GP or position filter may silently replace it. Zero is valid; null/missing/nonfinite and undefined ratios are excluded. Exposure caution is separate. Optional qualified/position comparisons must be additional and clearly named. Default percentile uses the same pool. This supersedes qualified-cohort defaults; the parent owns product questions and PRD drafting.

Later confirmed product choices: **free public player search, card creation and PNG export**; a **curated default card** with optional metrics/extra cards; **each player's own last N appearances (5/10/20) is the default recent-window definition**, with calendar-date ranges optional. Expanded metrics and two-player side-by-side comparison are premium candidates; the exact free/paid split remains to approve. These are planning inputs, not implemented entitlement rules.

### Metric contract and availability

`I` = individual counts; `O` = on-ice counts. For a chosen strength, gamelog tables are `nst_gamelog_{as,5v5,es,pp,pk}_counts` and matching `_counts_oi`. Their TOI is **seconds**. Seasonal `nst_seasonal_individual_counts` / `nst_seasonal_on_ice_counts` use **minutes** and include `team,strength,season`. Do not use TOI units interchangeably.

### Raw rank and percentile specification

For each metric, form one row per canonical NHL player after exact scope/source matching and trade aggregation. Include every valid finite value, including 0. Exclude null/missing, nonfinite, incompatible source contracts and zero-denominator rates. **Do not filter this default pool by GP, TOI, position, active roster status or fantasy relevance.** Historical players who appeared in the selected period remain eligible. No selected-player exception is needed.

Let `N` be that metric's valid-player count; `B` strictly better values, `W` strictly worse, `E` equal (including the target). Proposed and already supported by [calculatePercentiles.ts:13](/Users/tim/Code/fhfhockey.com/web/utils/calculatePercentiles.ts:13):

- Competition ordinal rank `1 + B`; display ties as `T-2 / 4` (ranks 1,2,2,4), not an arbitrary player-ID ordering.
- Percentile `100 * (W + 0.5 * E) / N`, same metric pool as raw rank. This convention gives a sole observation 50th percentile and does not force a unique leader to 100.
- Example valid values `[10,8,8,0]`: value 8 → `T-2 / 4`, 50th percentile; observed zero → `4 / 4`, 12.5th percentile. Missing fifth player is excluded, not converted to zero.
- Rank canonical unrounded values; formatting/rounding is separate. Define numeric precision once per metric/source, and do not break ties using hidden identity ordering. Every metric reports its own N; denominators can differ across a card.

If the cohort is incompletely ingested or source definitions cannot be aligned, show the actual valid player value with **rank/percentile unavailable: comparison coverage incomplete**. Do not market an unknown subset as a complete all-NHL rank. Optional `forwards`, `defense`, or `>=100 minutes` comparisons need their own explicit rank/N/percentile labels, never replacements for the default.

Exposure cautions are descriptive, not rank exclusions: show GP, selected-strength minutes and component counts. Candidate caution thresholds for product review: <10 appearances or <100 strength minutes; SH% <20 SOG; IPP <10 on-ice GF; oiSH% <100 on-ice SOG. These are proposed UI heuristics, not validated reliability guarantees and not a minimum sample requirement for raw rank.

### Freshness and honest states

Each metric needs numerator, exposure/ratio denominator, included/expected game coverage, source definition, effective through-date, fetch/compute timestamps and cohort snapshot ID. `last_updated` alone only dates a computation, including one performed on missing inputs. No silent prior-season fallback on a current-season share card. An explicitly selected prior-season card is a separate period.

States: **ready**, **observed zero**, **small sample** (value/rank retained when valid), **insufficient exposure** (undefined ratio), **missing source coverage** (name source and covered/expected games), **stale** (through-date visible), **source error**, **identity conflict**, **comparison unavailable**. Display missing values as an em dash with a reason; never a zero bar or 0th percentile. A selected-player value can be ready while its league rank is unavailable. Mixed metric availability should stay explicit in exports.
