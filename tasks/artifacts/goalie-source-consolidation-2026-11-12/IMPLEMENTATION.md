# Goalie source consolidation: local implementation and cutover

## Binding owner requirement (12 November 2026)
A goalie belongs to dated club-membership episodes. John's NJD 10/15 and PHI 1/1 produce separate shares plus **11/16 = 68.75%** overall. Do not add PHI's pre-arrival games, restart NJD's denominator, average percentages, or infer a trade date from the first appearance. Team games during membership include injury/scratch absences. A missing membership boundary remains unknown. The game's team is immutable history, not the goalie's current team field.

The numerator must be named: official starts, appearances, relief appearances and ice time are different quantities. Team crease share uses all the team's completed games in the window; player season workload uses the union of games within that player's club stints. Current-roster players' tenure shares need not sum to 100%. Historical frequencies are descriptive, not calibrated future start probabilities.

## Implemented locally
- `web/lib/projections/goalie/historyLedger.ts`: shared official-start resolver and team-window share arithmetic. Ambiguous/duplicate labels stay unresolved. Unresolved games remain in the supplied denominator; full shares are null, known portions stay available separately. Inputs are sorted before selecting last N, and duplicate team-game identities fail closed.
- `web/lib/projections/goalie/stintWorkload.ts`: versioned `goalie-stint-workload-v1` contract. Dated, nonoverlapping membership episodes; season/type/window scope; exact selected game ids; separate start/appearance/relief counts; completeness, unknown reasons, evidence identifiers and observation time. Counts and denominators aggregate, not percentages. Dates are precise, half-open intervals. It explicitly returns `not_a_forecast`.
- FORGE `queries/goalie-queries.ts` official-label adapter now delegates to the shared resolver. It no longer overwrites contradictory official label rows or resolves a partly unlabelled appearance set.
- `lib/socialShare/modules/creaseShift.ts` now calls the same canonical team-share arithmetic. Existing exports, schedule/finality rules and card shapes stay intact.

**Not yet a complete or deployed cutover.** The stint contract has synthetic acceptance coverage, not a populated membership source. The existing Game Grid dirty UI/API/history-source patch is untouched. Old helper copies outside the released ownership boundary remain pending explicit handoff; they are not secretly treated as migrated.

## Persistence contract needed before calling this one live source
Reuse authoritative schedule, WGO official labels and stored finality rather than adding a competing crawler. A canonical game-level ledger must retain season/game type, exact game/team/goalie identity, official starter label, appearance/relief state, finality/report completeness, membership-stint id and versioned source receipts. Membership episodes require dated transaction/eligibility evidence and explicit uncertainty when time is ambiguous. Never synthesize tenure from a player's first game or the current players.team_id. Unknown coverage remains null; no SQL `coalesce` turns it into a zero. Materialized window/stint summaries must derive from the same TypeScript/SQL contract fixtures, not become a second independent formula.

A read-only migration/preflight review must establish which stored membership evidence can satisfy this contract. Do not query or write production while the owner's current migration batch is in flight. Schema creation, historical population, cron/capture changes and release are separate actions, not accomplished by these local functions.

## Forward source and qualification
Retain `forge_goalie_candidates_v1` as the sole selected forward producer contract. It already distinguishes game/team/player identity, if-starts lines, raw start model output, credited goalie wins vs team wins, issue/cutoff clocks and unresolved mass. The existing public Grid reader intentionally withholds probabilities. Do not replace this with historic net share × team win, infer the partner as 1−p, or declare a singleton certain without an eligible-universe receipt.

Historic stint/team features may feed that producer after integration, but do not qualify it. Confirmed/projected news must enter through exact game/team/player evidence, status/freshness/expiry/conflict handling. A tweet about a goalie is not itself a start signal. Keep manual overrides distinct from sourced confirmation. Candidate eligibility, snapshot capture and pregame frozen receipts must be completed before held-out evaluation. Keep `starterBoardValidation` gates unchanged (including 200 games/30 slates). Existing L9b handoff explicitly says no candidate capture, qualification or promotion receipts currently exist. A production FORGE rerun alone cannot create calibration evidence.
