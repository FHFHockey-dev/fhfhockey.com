# npm audit triage

## Receipt and disposition

Chef’s existing receipt for this audit is `npm audit --package-lock-only --ignore-scripts --json`; its captured report is [`npm-audit.json`](npm-audit.json). This memo parses that JSON and `web/package.json`/`web/package-lock.json`; it did not rerun npm, install packages, or alter the lockfile. Reported count: **57 findings** — 3 critical, 32 high, 14 moderate, 8 low.

Severity is the audit’s package-level roll-up, not proof of exploitability in this app. Package-lock reachability to application code and affected-input exposure are **UNKNOWN** for every row. The root manifest says `next` is in `devDependencies` even though it is the app framework; its critical items are ranked first by production-app role, while the manifest/lock classification remains visible below. Lock `dev` annotations distinguish dev-only nodes from production-or-shared nodes; neither alone proves code reachability.

## Priority

1. **Next.js 15.5.22 — critical; app-runtime priority.** Audit associates two critical records with `next`: unauthenticated RCE on Windows-hosted servers and RCE in Image Optimization when AVIF is used. These are conditional advisory scenarios, not observed app exposure. The same package record also includes two moderate cache-poisoning advisories. The captured report suggests `next@15.5.28` without a semver-major change. Confirm release compatibility and affected deployment conditions before selecting it. Advisories: [GHSA-p293-qw3h-jr36](https://github.com/advisories/GHSA-p293-qw3h-jr36), [GHSA-2xp9-vwfh-vxw4](https://github.com/advisories/GHSA-2xp9-vwfh-vxw4), [GHSA-4jqv-mc3x-m676](https://github.com/advisories/GHSA-4jqv-mc3x-m676), [GHSA-mcj8-r9mp-w47p](https://github.com/advisories/GHSA-mcj8-r9mp-w47p).

2. **Vitest 3.2.7 / Tinypool 1.1.1 — critical toolchain.** Both are dev-only per the source lock; Vitest’s finding includes an `@vitest/mocker` path traversal record and Tinypool RCE advisories. npm proposes `vitest@4.1.12`, explicitly a semver-major move. Treat that as a migration candidate requiring test-runner compatibility review, not an automatic fix. Advisories: [GHSA-82fw-gwwq-j7x9](https://github.com/advisories/GHSA-82fw-gwwq-j7x9), [GHSA-5gmw-xhrv-c9v3](https://github.com/advisories/GHSA-5gmw-xhrv-c9v3), [GHSA-85c8-ppgw-ccpr](https://github.com/advisories/GHSA-85c8-ppgw-ccpr).

3. **Direct production dependencies needing focused triage:** Axios 1.18.1 (high; audit suggests 1.20.0, non-major), `puppeteer-core` 22.13.1 (high; suggested fix is a semver-major downgrade to 19.8.3, which should not be accepted blindly), `sanitize-html` 2.17.5 (moderate; XSS advisories), `moment` 2.30.1 and `yahoo-fantasy` 5.3.0 (moderate), and `ai` 6.0.83 (low; audit suggests 6.0.311). Specific references are in the complete inventory.

4. **Production-or-shared transitive high findings:** `postcss` under Next (8.4.31; captured report suggests the Next patch above), `undici` (7.29.0), `nanoid` (3.3.16), `sharp` nodes (0.34.5/0.33.5), and the Puppeteer chain (`@puppeteer/browsers`, `basic-ftp`, `extract-zip`, `get-uri`, `pac-proxy-agent`, `proxy-agent`). Lock metadata alone does not establish that a vulnerable API is called with attacker-controlled input.

## Suggested next step for Claude owner

Handle as a dependency-review ticket, not an `npm audit fix` operation: first review the app-runtime Next patch and direct production packages, then assess major-only toolchain suggestions and their compatibility. Keep the lockfile unchanged in this report-only task. On an approved candidate, compare before/after captured audit JSON using `npm audit --package-lock-only --ignore-scripts --json`; verify lock reproducibility with the repository’s `web/` `npm ci` procedure and run focused checks for the changed consumers. In particular, do not claim the critical Vitest findings are removed until the major runner migration is checked against this repo’s Vitest config/specs.
