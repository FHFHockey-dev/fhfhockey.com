## Findings

### AFULL-E2E1-01 — P2: crease/category fixtures leave real calendar/auth work outside interception

- **Location:** `social-share-crease-category.spec.ts:37–55,94–103,118–173,409–426`. The file's introductory claim at 12–14 says nothing reaches Supabase. `install` mocks only the chosen fictional Supabase origin. Most period tests add only `**/api/v1/social-share/posts/**`; they do not install a catch-all or the matchup-calendar mock used by `servePeriods:176–188` and the chosen-week GSAx case at 428–446.
- **Claim checked:** A fictional, local E2E fixture must actually contain all external/server fanout before being treated as offline evidence. This is an isolation defect, not proof of a bad calculation or historical production request.
- **Exact evidence:** The manifest probe executes the extracted `install` against a fake page, then the exact `fetchMatchupWeeks` helper against fake auth/fetch. It records the pattern set `[http://supabase.e2e.invalid/**, **/api/v1/social-share/posts/**]`. The generated request is `GET /api/v1/social-share/matchup-weeks`, `cache:no-store`, `credentials:omit`, with the fictional bearer. Neither the calendar URL nor an unrelated external URL matches these patterns.
- **Reachable path:** A ready mocked `goalie-period` snapshot mounts `PeriodControl`; its effect at `web/components/SocialShare/PeriodControl.tsx:24–28` calls `fetchMatchupWeeks`. `web/lib/socialShare/matchupWeeksFetch.ts:6–15` sends the request. The real local API's `web/pages/api/v1/social-share/matchup-weeks.ts:10` invokes `requireSocialShareAccess`; `web/lib/socialShare/access.ts:24–35` constructs a token client and calls `auth.getUser` before refusing an invalid fictional session. Browser route handlers cannot intercept this server transport. A valid configured client therefore attempts the auth request even if authorization later fails. With the required fictional server URL, this is an unwanted `.invalid` network attempt, not a successful production query. A reused or differently configured app server is not proven to use that fictional URL.
- **Minimal scenario:** Run the “Category Counts and the TGV grade” test with a fictional browser session and its declared post mock. Opening `/social-share/posts?post=goalie-period&week=4` initiates an unmocked calendar call; instead of exclusively fake responses, execution crosses into the real server's auth path. A missing key can fail client construction earlier; the issue is the admitted path when configuration permits client creation, not a claim that every launch sends a request.
- **Suggested fix/test:** Add the calendar response to common setup, deny unexpected browser/API requests by default, and use an explicitly isolated server configuration or server transport guard. Assert zero unmatched requests with a spy transport. Guarding only the test process's `.invalid` variable does not verify a reused server's compiled/runtime configuration. Do not rely on an invalid bearer to prevent the outbound auth check.
- **Affected readers:** Crease/category E2E evidence consumers and operators running these tests. Actual application access control still rejects invalid sessions; no auth bypass, user-row read, successful remote call, write or hosted incidence was observed. Main `social-share.spec.ts:107–126` already has the broader API/calendar mock and a browser external-deny route, so this finding does not accuse that suite of the same omitted calendar route.

### AFULL-E2E1-02 — P2: named byte-stability tests perform no equality check without optional pins

- **Location:** `social-share.spec.ts:445–484,709–728`; the two test names promise the same PNG bytes every run. Six equality checks depend on `SOCIAL_SHARE_PINNED_{GRID,EXTRA,PLAYER,TIERS,WEDNESDAY,TUESDAY}_SHA256`.
- **Claim checked:** A passing default test should distinguish a changed rendering from the pinned byte-stability expectation it names.
- **Exact evidence:** All six `if` statements were AST-extracted and evaluated with a fake empty `process.env` and deliberately changed digests. Result: **0 hash comparisons, 0 hash failures**. Supplying all six expected pins as `original` against `changed` produced **6 comparisons, 6 failures**. No actual environment variables or PNG files were read for this probe.
- **Minimal scenario:** A render changes PNG bytes but remains 1080×1080, retains valid signature/content and satisfies other assertions. With pins unset, the tests record the new hashes to evidence files and do not reject the changed bytes. They test exportability and generate evidence, not cross-run equality under that configuration. Conditional assertions are useful when pins are supplied; this is not a claim that they are always inactive or that a particular historical run lacked pins.
- **Suggested fix/test:** Make an explicitly named byte-regression mode require immutable baseline pins (fail or explicitly skip if unavailable), and distinguish evidence generation from equality validation. A deliberate digest change should fail that mode; missing baselines should never produce a “byte stability passed” claim.
- **Affected readers:** Screenshot/export regression evidence, release review and anyone interpreting these two test titles. P2 because this is test qualification only; it does not establish a production rendering defect.

## Calculation, missingness, clock and oracle review

**DRM:** The independently stated interval fixture checks Center 180 minutes, Substitute 61 shared minutes, and therefore **33.89%** in one direction and **100.00%** in the reverse direction; these assertions are stronger than merely echoing a matrix helper. Remaining pair totals and ordering derive from synthetic intervals with fixed games/period lengths. Last 7/30 calendar labels are frozen to November 12; partial qualification accepts two of three games and excludes pending input; wrong-version input is withheld. PP known-zero TOI and missing share remain distinct, and strength toggling reuses the qualified response. This preserves Decision152/provenance behavior but does not requalify provider parsing, actual five-game exceptions, atomic DB RPCs or actual PP clocks. The fake DB supports only the reviewed query subset: projection/select semantics and SQL behavior are not independently tested.

**Game Grid:** Known-empty, partial coverage, stale, postponed, missing forecast, stale selection revision, timeout/error, loading, request-count and source-specific retry cases are exercised in source. Independent schedule totals use a retained 32-team/52-game cell fixture: 104 team-games; removing Thursday's 14 games yields 76; removing a postponed game yields 102. The source records original matchups from March 2025 replayed on synthetic October 2026 dates, with synthetic IDs/states/receipts. This audit read those retained cells, not the original export or converter receipt; historical validation remains attributed to the fixture comments.

Five viewer-timezone cases preserve a future NHL Sunday start across UTC midnight, with 14 teams showing 1.3 opportunity and 18 showing 0.0 on a common scale of 2. Fixed browser dates and explicit `asOf` fixtures bound those cases; they do not establish every historical DST/calendar edge. Forecast expected means/goalie probabilities/expiry/revisions are deliberately hand-built. Display sum 3.6 reflects displayed 2.4+1.2 fixture values; no model calibration follows. Accessibility/overflow assertions range across phone/desktop sizes and use explicit small geometry tolerances; they were not run. Delayed mocked sources and recorded React timing are fixture behavior, not hosted performance evidence.

The date-range seam's `getSchedule:21–29` supplies data without `coveredDates`; it does not challenge the actual coverage omission already recorded as **AFULL-GRID5-01**. This is a limitation of that test fixture and the existing single finding, not a duplicate defect. Grid ordering/labels and positive schedule scores do not pin the unresolved quiet-night cap/lexicographic contract of **#444**. This batch neither closes nor reopens that item. The null Poisson replacement means the suite cannot validate Poisson odds, truncation or probability normalization.

**WiGO:** The deterministic hash and schema-shaped generator intentionally fabricate values. It generates 82 fixture dates × 16 league games and controlled missing VAN dates, but other per-player counts/rates are not guaranteed to obey hockey identities. The file explicitly says this. Example: generic GP can default to 76 while other generated rows use one-game shapes; such fixtures are unsuitable as scientific or pooled-rate oracles. `parseFilters/applyFilters` ignore OR/AND/unsupported filters and unknown columns; select projection omits full PostgREST join semantics; unknown RPC yields `[]`; single-row response behavior is permissive. These choices support a bounded layout fixture and are reported as evidence limits, not newly promoted statistical bugs. Null/unknown scientific handling must be checked in independent focused tests, not inferred from these broadly filled rows.

**Crease/category/GSAx:** Builders receive fictional observations and the actual UI receives builder-shaped snapshots. Independent assertions cover known missing schedule rows, official-start wording, TGV separation, tie counts, source lag/unavailable export gates, period boundaries and known fixture Category Count text. They do not qualify NHL/NST source joins or TGV as a predictive model. The export helper checks PNG signature only, while geometry tests check body fill/overflow. The first crease test builds `window:2` but wraps settings `window:10` (`:66–67`), then expects both a last-two-game subtitle and a token naming ten. This intentionally short fixture is internally inconsistent as a settings/result binding oracle; it cannot establish that the real endpoint computes the selected window. Later `serveCrease` cases parse requested settings and offer stronger window coverage. This mismatch is recorded as a test limitation, not a separate claim that the real loader uses the wrong window.

**Social share:** Extensive stale/partial/failed/known-empty source cases prevent ranks/export and distinguish failed recent reads from answered-empty reads. Same-edition export tokens, selection changes, refused capture after token mutation, no-refetch export, access denial and re-entry persistence are source-tested. PNG signature/dimensions and DOM/pixel geometry measure rendering, not input truth. Schedule row order, opponent/player/trend/tier/streak selections often use the **same production helpers** to build fixtures and compute expected lists; these can detect wiring/serialization/rendering disagreement but cannot independently catch a shared formula/ranking bug. Independent constants and algebraic fixtures are still needed for those helper definitions. Tests asserting formula text only pin the label.

Most social fixtures use wall-clock `generatedAt` and next week computed in the Node test process, while explicitly pinned tests fix browser time separately. The expiry case advances browser time beyond six hours. The optional captured-layer mode preserves captured series/provenance and labels the schedule as fictional, but skips without a file and cannot establish current live freshness. No capture was opened in this audit. Tuesday xG/GSAx labels use the served layer/NST disclosure contracts; none of these tests proves the retired custom champion is live, and the retirement closure is preserved.
