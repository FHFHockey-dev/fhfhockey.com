## AFULL-GRID5-01 — unobserved dates become zero-game schedule facts

- **Severity:** proposed P1, reachable missingness/reader mismatch; not P0 without live observation.
- **Location:** `web/components/GameGrid/utils/useDateRangeTeamGrid.ts:132–177`; summaries `:16–41`. Current consumer `web/components/GameGrid/DateRangeTeamGrid.tsx:68`, `:105–143`, `:266`.
- **Claim checked:** OFF, B2B, HOME and AWAY and date-density styling must distinguish an observed empty schedule from absent schedule coverage.
- **Evidence:** target source hashes in manifest; exact-source transform and summary probe `/tmp/astra-components5-probe.cjs`, retained output embedded in manifest. Independent components4 source trace confirms the table gate and numeric consumers.
- **Wrong behavior:** the hook loops every requested weekday and constructs `regularSeasonGames: 0` from an empty object without inspecting `schedule.coveredDates`. It returns the complete requested `dates` list with `loading:false,error:null`. `scheduleCurrent` only checks dates/loading/error, and the table gate lacks even that context check. All canonical teams can therefore receive zero totals, with unobserved dates styled as light/off nights. Partial coverage similarly becomes an apparently complete subtotal; a lone observed game on an otherwise unknown slate can acquire an unsupported off-night classification.
- **Minimal scenario:** request `2026-11-09..2026-11-15`; successful schedule payload `{data:{},numGamesPerDay:[0,0,0,0,0,0,0],coveredDates:[]}`. Actual transform emits seven rows with `regularSeasonGames=0,isOffNight=true,isHeavyNight=false`; actual summary gives `{off:0,b2b:0,home:0,away:0}`. Consumer admits the result. Expected: unavailable/partial calendar and withheld affected counts, not seven observed zeros.
- **Reachability:** client `lib/NHL/client/index.ts:102–111` returns the schedule envelope; server `lib/NHL/server/index.ts:465–481` explicitly records only source `gameWeek` dates in `coveredDates` while its legacy count array fills missing weekday counts with zero. The date-range hook ignores that distinguishing metadata. Ordinary selected-week `useSchedule` plus GameGrid coverage gate does use it; that containment does not apply to this hook.
- **Suggested fix:** preserve per-date coverage and request identity; admit a complete numeric range only when every selected date is covered. Partial displays must withhold affected totals/density/B2B rather than infer zeros. Add a hook-to-consumer fixture for absent and partial `coveredDates`, retaining a separate genuinely covered empty-week case.
- **Readers affected:** DateRangeTeamGrid schedule dates, OFF/B2B/HOME/AWAY totals and sort order, night-density styles; its goalie request context can incorrectly regard this range as current. No model probability was fabricated by this probe.
- **Existing test gap:** `useDateRangeTeamGrid.test.ts:14–31` tests only the pure summary with supplied complete metadata and inactive games; it never exercises coverage admission. `LeagueWeek`/`useSchedule` tests exercise the different selected-week path.

## AFULL-GRID5-02 — unfinished tied scores are labelled LOSS

- **Severity:** proposed P2, label-only under §5. The main matchup visual is the opponent logo, and the false final result is in the tooltip trigger's accessible label. No live-game sample was queried.
- **Location:** `web/components/GameGrid/TeamRow.tsx:333–354` (`MatchUpCell`).
- **Claim checked:** WIN/LOSS describes a completed result, not a live lead or an unstarted score placeholder.
- **Evidence:** exact target expression probe; server copies score and state without a finality gate at `web/lib/NHL/server/index.ts:532–551`; `useSchedule.ts:130–178` preserves the object, and `GameGrid.tsx:314–346,1043–1056,1560–1575` passes it into TeamRow after calendar coverage admission. Calendar completeness is not game finality.
- **Wrong behavior:** `hasResult` only checks scores against `undefined`; `usScore > opponentScore` means WIN and every other comparison means LOSS. `gameState` is not consulted.
- **Minimal scenario:** complete calendar; game `gameState:'LIVE',gameScheduleState:'OK'`, home score0 and away score0. Exact expression returns `Home vs Away. LOSS 0-0. Open game details.` A FUT game with supplied0–0 produces the same string; FUT score placeholders are a possible payload case, whereas LIVE scores are directly supported by this source path. LIVE2–1 similarly labels the current leader WIN before the result is known.
- **Suggested fix:** validate finite nonnegative scores and require FINAL/OFF before WIN/LOSS. For LIVE/CRIT, describe the current score/in-progress state; for FUT/PRE, retain pregame availability wording. Add unfinished-score tests to the existing MatchupOdds file.
- **Readers affected:** TeamRow normal/mobile schedule tooltip and accessibility label. `VerticalMatchupCell.tsx:41–55` also treats any present scores as a result branch, but only states the score without WIN/LOSS; do not claim it duplicates the false final-result wording.
