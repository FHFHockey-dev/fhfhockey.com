## AFULL-PRUN1-01 — P1: wall-clock goalie issuance makes later replay fail

- Claim: unchanged captured inputs and same code/configuration can reproduce the captured projection output hash.
- Source: `stages/goalie-stage.ts:815–829` sets candidate issuance `issued_at` from `new Date()`, then persists that contract in `uncertainty.goalie_candidates` at866–892. `gameRevisions.ts:142–154` strips only top-level created_at/updated_at. `run-forge-projections.ts:668–684` does not restore the issuance clock and rejects unequal output hashes. `inputCapture.ts:63–69` replays query results without controlling time.
- Evidence: exact isolated goalie candidate builder plus exact output hash produces different hashes when only nested issued_at changes by one second; changing only top-level updated_at leaves the hash identical. Retained `projrun1-probe-output.json` binds source hashes. This is source/local reproduction of the hash failure, not a full run or a hosted replay observation.
- Impact: a valid captured goalie output can fail deterministic replay solely due to replay wall time. Same-clock tests cannot qualify the later-clock guarantee.
- Suggested approved fix: pass a captured deterministic issuance clock through the calculation and use it consistently, or version a deliberately documented semantic hash that excludes only nonsemantic execution clocks. Preserve authentic original issuance evidence; do not silently overwrite it.
- Tests: add a different-wall-clock replay oracle with identical recorded inputs and a real goalie candidate output; current resume suite fakes both per-game stages and snapshot publishing.
