## Implementations and readers

`observedDeployment.ts` (309 lines) validates safe identities, two distinct teams, regular/playoff scope, unique player rows, common final game length, strict clock strings and safe totals. It rejects missing/duplicate/overlapping physical intervals, malformed player/period/shift IDs, out-of-period/end-of-game clocks, duration disagreement and incomplete/overlapping strength partitions. A strength transition may split one physical interval. Input ES/PP/PK totals must equal classified interval totals.

The event sweep applies exits before entries at the same timestamp, preserving half-open substitutions. Every player's all-strength and bucket TOI is measured in seconds; pair facts are same-team overlap seconds, not a symmetric percentage. Five-on-five requires five skaters plus exactly one goalie on **both** teams; other ES and unsupported special-team formations have separate coverage. Valid5v4/5v3/4v3 PP and corresponding PK units preserve actual skater sets; pulled-goalie/nonstandard formations are not invented as ordinary units. Regular OT is bounded to300 seconds; playoff OT periods use1200. The reusable even-strength unit builder reports player-seconds; dividing forward rows by3 and defense rows by2 recovers team clock duration, with explicit expected-duration checks. This conversion was checked against the bounded `teamUnitToiBuilder.ts:307–413` bridge; the entire builder remains its own later scope task.

Main-unit selection aggregates the same observed team/strength/kind/player set across games, unions game coverage, then chooses duration-ranked disjoint units with deterministic numeric-ID ties and caps4 forward lines/3 pairs/2 PP or PK units. It does not fabricate a co-occurrence group from individually popular players. Historical forward/defense role changes cannot put the same player twice in a main five-on-five lineup. Inputs are copied; known seconds overflow is rejected. This is the documented duration-first selection, not a claim of a globally optimized lineup. Callers `ObservedUnits.tsx` and `useDateRangeMatrixData.ts` were fully reviewed in the earlier component batches.

`readMatrix.ts` (307 lines) validates team/season/date/venue/opponent/game-ID scope and bounds retained queries to200 games,400 heads and20,000 shift/roster rows. It never fetches a provider or ingests. Retained PBP identity, FINAL/OFF state and final-clock calculation are checked separately from qualified input/relationship status, hashes, source heads, versions and row-count agreement. Missing/unverified/stale games remain in coverage while only accepted games enter numeric populations. Stored `games.game_state` is not substituted for this retained-source qualification; neither path was queried.

Historical roster identity/position and PBP hash are enforced. A missing roster skater is unknown unless a final, same-generation boxscore proves complete roster identity plus explicit zero TOI, zero shifts and zero applicable event counts. This exception never creates a shift row, appearance or unit for the nonparticipant. Expected shift-row counts, player/team/opponent/date/season, final game length and recomputed versus stored pair seconds must agree. Names/sweaters are qualified before accumulating a game's results. Double manifest/head reads detect a source publication change during the read; missing changed heads exclude the game. This is a consistency check over the published generation, not an independent database transaction/snapshot guarantee.

Each strength reuses accepted normalized metadata with recomputed strength TOI/pairs; wire conversion turns sets into arrays. Card stats receive accepted IDs only. Existing component `fetchAggregatedData` source review covers the card adapters, including qualified PP-share behavior. The raw response keeps excluded counts/reasons, observed-unit limitations, accepted GP and known-zero strength exposure separate. Neither this batch nor one-minute synthetic fixtures certify that a provider supplied a complete real NHL timeline: that remains upstream source/materialization qualification.

`types.ts` (33 lines) contains static wire shapes for strengths, game states, totals, excluded coverage and observed units. It computes nothing and performs no runtime validation; one whole-file no-math row records that boundary.
