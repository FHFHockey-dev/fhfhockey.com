## Findings for Chef review

### AFULL-PICKUP-W01 — proposed P1: irrelevant goalie selection changes skater score by reintroducing GP%

- **Expected definition:** the default composite intentionally excludes GP%, because the inputs are season totals that already reward playing time (`PlayerPickupTable.tsx:2638–2647`). Changing only a goalie metric must not change which skater metrics contribute to the score. The filter UI permits independent metric toggles (`661–663`, `745–760`, `1014–1022`).
- **Source defect:** global mode depends on how many of the full 18 keys are selected (`2678–2689`). With all selected, the skater uses its GP-excluding composite (`2703–2709`, `2722–2725`). Deselect any goalie-only key such as GAA: the global mode becomes multiple; the skater's still-identical applicable selected set now goes through the mean that **includes GP%** (`2712–2715`, `2742–2754`). The algorithm therefore changes even though no skater selection changed. The single-selection “Other Avg” branch also includes GP in the background mean (`2730–2738`); the main confirmed scenario needs only the multiple branch.
- **Concrete scenario and exact-source result:** two skaters A/B have points 10/20, GP fractions 1/.5, all other season metrics unknown. Midrank points are 25/75; GP midranks 75/25. All-selected scores are **25/75**. Uncheck only goalie GAA; skater scores become **50/50**. This is a score/rank change caused solely by an irrelevant goalie setting. The retained pure probe executes the original percentile and score callbacks, not a reimplementation.
- **Reader reach:** both desktop (`1460`) and mobile (`1675`) show the resulting number; both score sorting and pagination use it (`2780–2804`, `2830–2832`, `2881–2884`, `3078–3100`). GameGrid mounts this component with selected-period context at `1077` and `1627–1630`. No flag or malformed provider value is required.
- **Test boundary:** existing `PlayerPickupTable.test.ts:285–300` correctly pins default scores 25/75 and missing HIT `—`, but never changes a metric checkbox. It does not pin this branch. The exact-source probe passed its observation assertions; no UI test was run.
- **Suggested correction/test:** derive one explicit per-player scoring set and use it consistently across modes, with the established season-total GP policy. If GP is intentionally independently selectable, make its contribution policy consistent and explicit rather than changing it through unrelated categories. Extend the existing composite test: toggling GAA must leave both skaters' score/order unchanged; exercise GP selection policy directly and repeat on mobile. Do not undo the established default exclusion.

### AFULL-PICKUP-W02 — proposed P1: no known performance still produces numeric zero and a ranking

- **Expected:** rule 5 preserves unknowns. A complete absence of eligible metric evidence is not a measured low performance. A player can be eligible for the Yahoo pool while season performance is unavailable; the mapping adapter explicitly preserves SQL nulls (`2128–2245`).
- **Source defect:** per-metric percentiles correctly return null (`2568`, `2589`), but `assignPercentiles` turns an empty known-metric set into composite **0** (`2647`). Default scoring forwards that number (`2723–2724`). Multiple selection also turns `selectedCount===0` into 0 (`2753`); single mode substitutes 0 for an unknown selected percentile (`2740`) and for an empty other-metric average (`2738`). These are distinct from the intentional “None” selection, which is labelled N/A; the defect applies when actual requested metrics have no observations.
- **Concrete exact-source result:** an eligible skater with every performance metric and GP null retains all null percentile boxes but gets composite/display **0**; selecting only points still creates `sortByValue=0` and `displayScore=0`. Desktop/mobile render `0.0` after the GP request completes or fails (`1460`, `1675`, `2436–2444`, `2808`), and the normal numeric sorter uses it. Source scoring types require numbers (`64–75`), so downstream missingness cannot survive.
- **Reach:** both mounted GameGrid pickup tables; unknown-data condition, source-confirmed reader path. No hosted row prevalence asserted. Partial known-metric averaging is deliberately not reopened here; this finding is restricted to **zero known inputs**.
- **Test boundary:** the missing-metric test checks one missing HIT while points are known; the idle test largely uses rows with absent metrics but checks only label/order, not absence of fabricated scores. Neither asserts all-unknown score semantics. Pure probe records original callbacks returning 0.
- **Suggested correction/test:** preserve nullable score/sort values and evidence count when the contributing set is empty, display unavailable, keep those rows separate from ranked known observations in both directions. Extend the existing component test with eligible all-null player, known-zero performance player, GP loading/failure completion, single/multiple/default selections and both layouts. A measured zero in a nonempty cohort must remain eligible for its genuine midrank.

### AFULL-PICKUP-W03 — proposed P2: ascending ownership/GP/off-night sort promotes unknowns

- **Source:** the generic sorter recognizes `N/A`, null and undefined (`2858–2862`), then returns **−1 for an invalid A in ascending order** (`2864–2865`). Header interactions first choose descending and then toggle ascending (`2899–2905`); Own%, GP% and Off-Nights are directly offered sortable columns (`1249–1263`, `1527–1538`).
- **Exact-source scenario:** Own% values unknown, measured 0 and measured 10 sort ascending as **Unknown, Zero, Ten**. Descending correctly gives Ten, Zero, Unknown. Unknown ownership is included by default (`1884`) and properly labelled; the defect is its placement among lowest-ownership candidates, not a hidden numeric coercion. The same comparator applies to null GP and `N/A` off-nights.
- **Reach/impact:** direct current component source path, two ordinary header clicks; P2 presentation/ranking usability, not a false ownership measurement or waiver-availability claim. Season/metric/source missingness fixes remain intact.
- **Test boundary:** existing ownership tests cover filters, 0 versus missing and expiry, but never header sorting. Exact comparator callback probe passed; UI runtime not run.
- **Suggested correction/test:** separate unavailable rows independently of ascending/descending multiplier; keep measured zero correctly ordered and unknown last in either direction. Extend existing tests with unknown/0/10 and both directions for Own%, GP% and Off-Nights.
