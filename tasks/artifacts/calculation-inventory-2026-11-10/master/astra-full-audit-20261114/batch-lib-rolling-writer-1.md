## Full traversal and contracts

- Writer setup/options: environment loading and service client are module-level; the audit never imports that module. Regular-season admission tolerates missing `type`. Strength normalization silently removes invalid tokens; invalid-only normalization becomes unspecified/all, but API validation must be considered before promoting a separate finding. Player IDs, date-scoped selection, explicit resume, write-window filters and historical read-window removal were traced.
- Storage: ranking select fields and explicit TOI/context exceptions survive pruning. Dropped-column inventory is separate from preview compaction. Aligned count payloads validate identity/anchor; null explicitly clears prior support. Window count payloads retain actual appearances/current-season membership. Historical and deprecated compatibility namespaces differ. All-null pruned inputs still create the clearing sidecar. No generation coherence exists across the two writes (02).
- Transport: REST errors retain structured code/details/status; timeout splitting is sequential, halves to single rows and then fails. Outer retry is bounded to five attempts, with exponential delay/jitter and phase-deadline checks. AsyncLocalStorage isolates run deadlines. This is phase-boundary abandonment, not an in-flight network cancellation guarantee. A non-deadline worker failure rejects `Promise.all`; sibling work is not canceled, so error receipt does not imply no further writes. No stronger atomic-run guarantee was established.
- Source acquisition: paged games/WGO/player identities use explicit sort, while NST per-player tables have bounded six-query fan-out through the limiter. Whole historical data feeds accumulators; requested season/start filters apply to writes. WGO remains the appearance spine, with exact/canonical game and team mapping and strength-specific TOI. Rates/denominators use the selected source adapters; ratios pool matched components. Unknown metric components remain null, except the window-membership defect (01). Split-strength unknown TOI is treated as no observed positive-TOI appearance; this remains a source qualification question for the downstream participation contract.
- PP: optional legacy unit/context fields remain distinct from Decision152 share. Served share consumes qualified stored clocks; N/A zero-clock games are excluded from a ratio, unavailable/missing clocks stay unsupported, and qualified clock with no player PP row gives measured zero participation. The flag-off path deliberately preserves prior behavior. Global PP/line cache lifetime violates refresh expectations (03).
- Processing: each strength keeps simple, ratio, support, historical and team-of-record accumulators; ratio appearance anchors and explicit count-support windows are distinct from legacy scalar windows. Season/three-year/career rates use paired denominator totals and three-year season keys. Storage rate aliases named `total_lastN` remain rates by the declared compatibility contract. This audit does not reinterpret those names as counts.
- Runners: dry-run builds and observes payloads without POST. Full-refresh truncate guards reject player-scoped, dry-run and incompatible bounded requests before execution. Default work is bounded by explicit player/row concurrency; end-of-run continuation uses the contiguous completed player prefix, redoing abandoned/later-completed players. Write diagnostics report missing coverage/freshness but do not establish a separate correctness qualification gate. No cleanup/truncate or refresh action executed.
